# 对标准符合性的一次算术核算（2026-11-14）

## 0. 一句话结论

在**同一代固件**（`61ca1da3…` / 184146 B）的 **232 轮已发布结果**上，三视图中位估计器
（`tools/covered_bp.py`）的池化误差是 **MAP −0.71 / sd 6.64、SBP +0.53 / 7.24、DBP +1.78 / 7.12**，
三项**都落在 AAMI/ISO 81060-2 的 |mean| ≤5、sd ≤8 之内**，BHS 分级三项都是 **A**。
七档里 **6 档三项全过**，唯一不过的是 Preset 2（sd 15–19，由两轮面板未确立的补采轮造成）。

**但这不等于"符合标准"**。这是一个台架模拟器上的算术结果，不是临床验证；而且 sd 只剩 10%
余量、偏移是样本内拟合、每档只有 19–84 轮。四条不能宣称的理由见 §4。

---

## 1. 两个经常被混在一起的问题

| 问题 | 判据 | 本工程能不能答 |
|---|---|---|
| 算法**算术上**满足精度判据吗？ | AAMI/ISO 81060-2 clause 5.2.4：配对差的 \|mean\| ≤5 mmHg 且 sd ≤8 mmHg | 能，用现有数据算 |
| 设备**通过临床验证**了吗？ | ISO 81060-2 流程：≥85 名受试者、每人 3 组配对、受训观察者、规定受试者筛选、参考水银柱 | **不能**，本台架禁止人体接入 |

市面宣传常写的"±3 mmHg"指的是**静态压力示值误差/显示分辨率**，不是测压精度。测压精度的
通行门槛就是上表第一行；BHS 协议则用"落在 5/10/15 mmHg 内的百分比"分级
（A ≥60/85/95%、B ≥50/75/90%、C ≥40/65/85%）。

---

## 2. 口径与排除

- 数据源：`data/reports/covered_algorithm_20261114.json`（`tools/covered_bp.py --score` 的输出，299 份导出）。
- 只统计 `status == 'ok'` 的轮次（拒判不是估计值，不能进误差统计）。
- **固件代次必须一致**：读每轮 `<run_id>.metadata.json` 的 `firmware_hex_sha256`，
  不是 `61ca1da3…` 的轮次剔除 —— 共 **11 轮**（6 轮 2026-11-06 的 `bb33a3a4…` 老固件、
  5 轮 2026-11-14 傍晚 `f72c4cca…` 控制窗实验版；后者见
  `data/reports/deflate_loop_limit_cycle_20261114.md`）。理由：一个语料是一代固件，
  换代的波形不能与它混算。
- 剩 **232 轮**。

## 4. 为什么仍然不能宣称"符合标准"

1. **sd 余量只有 10%**。SBP 7.24、DBP 7.12 对门槛 8.0，MAP 6.64 也只有 17%。
   而且 MAP −5.31 / DBP −1.16 两个偏移是**在样本内拟合**的（`frozen_baseline_v2` 18 轮），
   不是前瞻得到的常数。
2. **轮次 ≠ 受试者**。ISO 81060-2 要求 ≥85 名受试者 × 每人 3 组配对；这里每档只有 19–84 轮，
   且全部来自同一台模拟器、同一只袖带、同一套气路。重复测量压缩不了系统偏差。
3. **真值是模拟器**。BP Pump 2 按面板预设合成示波包络，它给的是"面板上的数"，不是听诊值。
   用模拟器当参考来自证，逻辑上闭不了环 —— 只能说"对台架波形达到 5/8 判据"。
4. **静态压力示值超差**。独立于测压精度的另一条判据：17 点静态交叉验证最坏 **±5.7 mmHg**
   （`data/reports/pressure_axis_accuracy_20261111.md`），而 ISO 对静态示值的要求是 ±3。
   这一条现在就不达标，且与算法无关，是传感器链路的问题。

## 6. 复现

```powershell
# 1) 先打分（约 4 分钟）
python tools/covered_bp.py --score --json data/reports/covered_algorithm_20261114.json

# 2) 再按标准口径核算（排除异构固件、去掉拒判轮）
python tools/standard_conformance.py --out data/reports/standard_conformance_20261114.json
```

`tools/standard_conformance.py` 只读上面那个 JSON，不改任何数据、不调参数；固件代次从每轮
元数据读，不写死在脚本里（只有"被认可的那一代"是常量 `PUBLISHED_FIRMWARE_HEX`）。
