# 在数据集回路测容积：操作步骤与判读

> **容积数字已更新（2026-11-09）**：本文中的 **153 cc** 是用面板每搏设定值反推的
> 估计量，已被直接测量取代 —— 数据集回路实测 **320 cc（区间 278–320 cc）**，
> 见 `data/reports/dataset_loop_volume_result_20261109.md`，交叉验证见
> `data/reports/volume_crosscheck_20261109.md`。**引用容积请用 320 cc。**
> 本文保留作为该数字的来历与误差讨论记录。

日期 2026-11-09。目的：测出**数据集回路**（MCU + 阀 + 真袖带）的密封容积，把 09 日那个 362 cc 的不确定性结掉。

前面的数：

| 回路 | 数 | 怎么来的 |
|---|---|---|
| 阀外回路（BP Pump 2 SOURCE 模式 + 袖带 + 三通 + 注射器） | **362 cc**（区间 320–405） | 六点实测，见 `data/reports/valvefree_result_20261109.md` |
| 数据集回路（MCU + 阀2 + 袖带，59 轮数据用的那个） | **未测**，只能按面板 dV 反推 153 cc | 假设面板标称 0.55 cc 为真值 |

两者的差恰好可能是 BP Pump 2 内部那个 290 cc 罐体。而且 SOURCE 模式的 362 cc 还包含仪器自己的 **20 cc 主气室**，那 20 cc 不在数据集回路里。所以这一次测量不是"再精修一下数字"，而是**二选一定案**：

```
E = 342 cc   罐体在 SOURCE 模式里关着  → 袖带气囊约 315 cc
E =  52 cc   罐体在 SOURCE 模式里开着  → 袖带气囊约 40 cc
```
没有第三种可能，因为 20 与 290 是手册的固定标称值。而 **E 本身就是数据集回路的容积**（362 减掉那 20 cc 主气室）。

---

## 一、为什么换到数据集回路测

1. **这是唯一能落到数据集上的数**。数据字典里的容积、面板 dV 的可信度、跨批次幅值可比性，全都依赖这一个数。测阀外回路只回答"BP Pump 2 里有多少气"。
2. **有轨迹而不是六个手抄的读数**。串口 20 Hz 记录，阶跃时刻由程序自己在压力曲线上找，不必依赖人工计时——09 日那次的三个漂移率互相矛盾，根子就是没有轨迹。
3. **能同时做掉泡沫蠕变的对照**。同一套脚本换个起始压力再跑一次即可（§五）。

---

## 二、接线（只动气路，电气不变）

```
        泵(PC8) ──► 阀1(PB8) ──► 三通 ─┬─► 真袖带
                                      ├─► 传感器 P1 (MPXV5050GP)
                                      ├─► 注射器（26 mL，接在针头侧）
                                      └─► 阀2(PC1) ──► 大气
```

四条要点：

1. **BP Pump 2 从三通上摘掉，它的口堵死。** 不摘的话它的主气室（20 cc）和泄压阀都会进回路，而且它空闲态的内部通断没有文档可查。这一轮不要它。
2. **阀2 必须在"三通 → 大气"这一支上，不能在"注射器 ↔ 袖带"中间。** 现在就是对的（`vent` = PC1 HIGH 通大气，`seal` = PC1 LOW 关闭）。如果阀2 坐在注射器和袖带之间，`seal` 会把活塞和袖带隔开，拉活塞就什么也测不到。
3. **注射器接在阀2 的上游**，也就是和袖带、传感器同一个节点。09 日那张连接图（`data/reports/syringe_connection_20261109.png`）就是这个拓扑。
4. **袖带保持 09 日实测时的绑法**。这一轮不换袖带、不重绑——不然测出来的差异分不清是罐体还是绑法。

## 三、操作步骤（约 6 分钟，你只需要在三个时刻各做一次动作）

脚本会打印**绝对时钟**，例如：

```
   PULL to the hard stop at  10:42:31   (hold 130 s)
   PUSH fully home at        10:44:41   (hold 90 s)
   script finishes at        10:46:11
```

倒计时到 30 / 10 / 5 秒会有提示。全程你只要在时刻做一次动作，其余可以放手。

| 阶段 | 你要做什么 | 时长 | 为什么 |
|---|---|---|---|
| 0. 预检 | 什么都不做。注射器活塞**先推到底**再开始 | ~10 s | 脚本要确认封阀零点 ≤1.2 mmHg、raw 峰峰 ≤12 counts。手一碰活塞峰峰就上去了，直接报错拒绝 |
| 1. SETTLE | 活塞**夹住/顶住**在 0 mL，别碰 | 90 s | 压缩热没散完时读数偏低。11-08 实测前 30 s 掉 15%，之后才稳态。90 s 是安全余量 |
| 2. PULL | **看到提示就拉到底**，然后保持在硬停止位不动 | 130 s | 26 mL 全行程。压力会把活塞往外推（240 mmHg 下 0.85 kgf），必须用夹子或扎带锁住，手按不算 |
| 3. PUSH | **看到提示就推回 0 mL**，保持不动 | 90 s | 用回程的漏气速率做"有没有进气"的检查（§四） |

**为什么"到底"而不是某个刻度**：09 日之前四次失败，全部是"在压力下做精确动作"出错，没有一次公式错。硬停止把动作变成不要求精度的一件事。

**为什么不需要你先记读数**：整段压力轨迹由串口 20 Hz 落盘，阶跃时刻程序自己找。

## 四、判读（脚本跑完会自动打印）

### 4.1 主结果

```
PRIMARY  at 91.8 s: home 190.83  pulled 50.57  step 140.25
VOLUME   xxx.x cc    bracket aaa.a - bbb.b cc
```

主结果在**拉的瞬间**取值——这是两支路摩尔数相等的唯一时刻，气体定律只在这一刻成立。副结果在拉出平台尾部取值（B 不外推），两者之差就是"拉出侧斜率"这项系统误差的大小。

自检结果（`tmp/dataset_loop_step_selftest.py`）：真值 110 / 150 / 300 / 362 cc 分别返回 110.1 / 150.3 / 300.5 / 362.9（误差 ≤0.3%）；拉出平台加 0.8 mmHg 手噪只挪 0.6 cc。

### 4.2 三个可判定的失败模式，脚本会直接拒绝

| 现象 | 脚本的判据 | 含义 |
|---|---|---|
| `plateau B is not flat (...)` | 斜率 > 24 mmHg/min | 活塞还在被手按着（手按噪声 17 倍于松手） |
| `plateau A is rising (...)` | 斜率 > +0.4 mmHg/min | 阀没封住 |
| `plateau B reached 0.0 mmHg ...` | 拉后读数 < 5 mmHg | 撞到 `ads1115.c:215-218` 的负压钳位，读数全是假的 |

最后这条是**真实的坑**：150 cc 回路从 120 mmHg 起拉 26 mL，算下来应该是 −10 mmHg，固件会把它钳到 0.0 并且看起来"很平"。所以**目标压必须够高**。

### 4.3 目标压选多少

不同候选容积下拉到底应该读到的压力（拉前 = 目标压）：

| 回路容积 | 200 mmHg | 240 mmHg | 280 mmHg |
|---|---|---|---|
| 362 cc | 135.7 | 173.0 | 210.3 |
| 300 cc | 123.4 | 160.2 | 197.1 |
| 150 cc | 58.2 | 92.3 | 126.4 |
| 123 cc | 32.5 | 65.5 | 98.5 |
| 72 cc | 钳位 | 钳位 | 钳位 |

**建议用 240 mmHg**：123 cc 以上的所有候选都读到正数；如果真钳位了，那本身就是"小回路"这一支的答案。

保持正压所需的最低目标压：123 cc 需 167 mmHg、150 cc 需 138 mmHg、72 cc 需 **281 mmHg**（固件上限 280，所以小回路这一支只能拿到"低于 123 cc"的界，但那也足够否掉"袖带很大"）。

### 4.4 回程那一段怎么读

```
ROUND TRIP  drift -6.00 -> -6.00 /min  PASS
```

判据是**速率**，不是压差。压差不能判：漏气随压力变化，低压漏得慢，恒速外推会高估压降，让实测值偏高；活塞边缘进气也让它偏高——同一个方向，区分不了。速率能判：固定漏孔在低压必须更慢，所以回程速率不高于起始速率就是 PASS。

## 五、顺手做掉泡沫蠕变的对照（可选，30 秒）

09 日三个漂移率 6.0 / 1.0 / 3.0 互相矛盾，按漏孔物理应该只差 13%。要让它讲通需要 `P_abs^25`，而真实漏孔是 `P^1`。最可能的原因是袖带内的开孔泡沫在蠕变（受压缓慢变薄 → 空间变大 → 压力降；拉出后回弹 → 空间变小 → 压力升）。

**检验方法**：同一套脚本，把起始压降到 150 mmHg 再跑一次（`python tmp\dataset_loop_step_20261109.py 150`）。

- 两次容积一致 → 蠕变不主导，主结果可信；
- 两次容积差异大 → 蠕变主导，主结果要按泡沫模型修正，或者换一个无泡沫的刚性容积（例如把袖带换成硬瓶）。

150 mmHg 时 123 cc 以上回路仍然正压（见 §4.3），所以这一次也能给出数。

1. **串口在**：`python tmp\port_status_20261109.py` 应列出 `COM6 | USB 串行设备 | USB VID:PID=FAED:4870`。现在（写这份文档时）系统里**一个串口都没有**，MCU 的 USB 没插。
2. **MCU 固件版本**：`cal` 应读回 `82.326 / -19.89`，`[Status]` 应 `cal=VALID ads=ONLINE stream=ON`。
3. **标定不会被动**：脚本只发 `status/pins/cal/fault/vent/seal/target/start`，不动 `cal write`。
4. **外壳上电顺序**：继电器先于 MCU 断电、MCU 先于继电器上电（AGENTS.md）。
