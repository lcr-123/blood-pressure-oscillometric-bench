# 压力轴重算账本（2026-11-26）：尺子换了，跨天池从 6/7 掉到 5/7

## 0 一句话

2026-11-26 上午把压力轴从 `82.326 / -19.887` 改成 `81.529 / -20.03` 之后，仓库里所有已发表的血压数字仍然是旧尺子算出来的。本报告把 645 份导出按新尺子重算了一遍，结论是：**跨天批次的 `covered_bp` 七档过 AAMI 从 6/7 变成 5/7，掉的是 P4 的 SBP（-2.91 → -5.68），另 P2 的 SBP 从 -3.97 恶化到 -5.71**；T0「5 mmHg 内」可声明格从 0/21 变成 **1/21**（P1 MAP；注意 `pressure_axis_refit_20261126.md` 当时把近似算成 2/21，见 §8）；T2、T3 基本不动（T3 对轴免疫）；T1 仍然 FAIL。冻结门只多拒 1 份（`standard255_195_20261105-103250`，斜率 −3.977 → −4.055，越 4.0 线），跨天批次仍只有 `135554` 被拒，**已经跑完的 266 轮一轮都不用重采**。

## 1 为什么要重算账本

`data/reports/pressure_axis_refit_20261126.md` 只回答「尺子准不准」：17 点静态交叉验证从 8/17 落规格变成 17/17，最坏总误差 5.715 → 2.840 mmHg，改标定后的两组独立复测 4/4 与 4/4。它没有回答另一个问题：**换了尺子之后，用旧尺子算出来的那些血压误差还成不成立。**

不成。旧轴在 200 mmHg 以上系统性偏低 2–3 mmHg，`covered_bp` 的估计误差里有一部分正是这个偏移。所以 6/7 这个成绩里，至少 P4 那一档是靠「尺子错了 + 算法偏了」互相抵消凑出来的。重算账本就是把这笔账摊开。

## 2 方法：只改一个入口

`validity_v2.check()`、`reference_bp.estimate()`、`covered_bp.views_for()`、`tools/crosstday_judge.py` 的 `collect()` 全都通过同一个函数取压力：

```python
capture = reference_bp.load(export_path)   # tools/reference_bp.py:83
```

所以重算不需要改任何工具，只要在内存里把这个函数的返回值换掉：

```python
S = 81.5286 / 82.326            # 0.9903141170468626
C = -20.0279 - (-19.887) * S    # -0.33352315428904333
capture['pressure'] = [p * S + C for p in capture['pressure']]
```

几个必须说清的口径细节：

- **只动 `pressure`**。`v` / `e` / `s` 不重映射——电压包络与标定无关，`band` 视图是对原始电压做 1–2 Hz 带通，动它会引入假装出来的变化。
- **轴变换是仿射的**，`p_new = (1+b)·p_old + a`，截距也要乘 `(1+b)`。写成 `intercept = OLD_INTERCEPT + a` 会让 250 mmHg 再偏 0.2 mmHg。
- **`covered_bp` 的偏移常量在 raw 上加**（`tools/covered_bp.py:188-190`：`detail['map_mmhg'] = round(raw['map_mmhg'] + MAP_OFFSET_MMHG, 2)`），所以换轴后 raw 整体移 −0.33 mmHg，偏移要么保持原值、要么机械平移。第 5 节专门处理这一条。
- 脚本跑完 `finally: reference_bp.load = _ORIGINAL_LOAD`，工具文件一行未改，`tools/verify_freeze.py` 的 3 份冻结记录不受影响。

## 5 偏移常量要不要跟着改

`covered_bp` 的三个偏移（`MAP_OFFSET_MMHG = -5.31`、`DBP_OFFSET_MMHG = -1.16`、`SBP_OFFSET_MMHG = 0.0`）是在 `frozen_baseline_v2` 上拟合出来的，**冻结记录在 `data/protocols/reference_bp_freeze_v5_candidate.md:43-45`**。它们是在旧轴上拟合的，所以换轴之后必须回答一个问题：这些偏移还算不算数。

三种做法我都算了：

| 做法 | 偏移值（MAP / SBP / DBP） | 来源 |
|---|---|---|
| 保持不变（当前提交状态） | −5.31 / 0.0 / −1.16 | v5 候选冻结值 |
| 机械平移 `offset − C` | −4.976 / +0.334 / −0.826 | 让偏移在新轴上等效 |
| 在新轴上重拟 | −3.820 / +1.855 / +0.990 | `frozen_baseline_v2` 的 14 个可发布轮 |

三组变体的跨天池读数：

| 变体 | 跨天可发布 | SBP | DBP | MAP | 七档过 | 失败档 |
|---|---|---|---|---|---|---|
| 旧轴 + 旧偏移（已提交） | 235 | +0.503/6.309 | +2.264/3.729 | −0.496/4.031 | 6/7 | P2 SBP |
| 新轴 + 旧偏移 | 235 | −1.080/6.495 | +1.047/3.601 | −1.855/4.057 | 5/7 | P2 SBP、P4 SBP |
| 新轴 + 机械平移偏移 | 235 | −0.750/6.495 | +1.380/3.601 | −1.517/4.057 | 5/7 | P2 SBP、P4 SBP |

**结论：偏移怎么选都不改变 5/7，也不改变失败档集合**，只把 pooled 均值挪 0.3–0.7 mmHg。理由很直接——偏移是全局常数，而 P4 的失败是「轴在 255 mmHg 附近差了约 3 mmHg」，按档位幅度不同，全局常数补不平。

所以本报告不改 `tools/covered_bp.py` 的任何常量。理由：

1. 改了就是破 `reference_bp_freeze_v5_candidate.md` 的九个冻结常量，必须出 v6 或 amend，那是另一件事；
2. 改了也不改变成绩，收益是 0；
3. 保留旧偏移并**明确标注它是在旧轴上拟合的**，比偷偷平移更诚实。

代价是：现在仓库里的 `covered_bp` 常量与当前硬件轴不匹配。这条要写进 `dataset_limitations.md`，留给 v6 处理。

## 7 门与状态的变化

`validity_v2.py` 读的是 exported `p`，所以换轴会改变峰窗斜率的判定。

- 旧轴门拒绝：**10 份**。新轴门拒绝：**11 份**。
- 唯一新增：`standard255_195_20261105-103250`（`legacy_firmware` 层），峰窗斜率 **−3.977 → −4.055**，越过 4.0 的限。它本来就不是可发布轮（旧轴下状态是 `unresolved_views`），所以对成绩没有影响。
- **跨天批次仍只有 `135554` 一轮被拒**（阀失节流那例）。也就是说：**换轴没有推翻任何一条已经发表过的判定**，也不需要重采任何一轮。
- 解码失败 0 份，两轴相同。

## 9 结论：能写什么、不能写什么

能写：

1. 跨天批次 235 轮，在新压力轴下 `covered_bp` 三视图中位估计器：MAP −1.86/4.06、SBP −1.08/6.49、DBP +1.05/3.60，**七档 5/7 过 AAMI**（P2、P4 的 SBP 不过）。
2. T0：**P1 MAP 一格可声明「5 mmHg 内」**（+0.602，CI `[−3.56, +4.76]`，n=37）。21 格里 1 格可声明、1 格 FAIL、19 格 undecided。
3. T2 通过（Δ_wrap −1.073，远小于检出阈值 1.81）；T3 SBP/DBP 日项复现、MAP 不复现，且**与压力轴无关**。
4. 压力轴重标定不推翻任何已发表判定，266 轮跨天数据不需要重采。

不能写：

1. 不能写「6/7 过 AAMI」——那是旧轴的数，新轴是 5/7。
2. 不能写「P4 通过」——旧轴下通过是尺子错了碰巧抵消。
3. 不能写「T0 0/21」——新轴下 P1 MAP 可声明。
4. 不能引用「frozen_v2 静默 20 轮」而不说口径——新轴下是 26。
5. 不能把三个池合并报覆盖率（协议 §6 禁令不变）。
6. 不能写「轴修好了，精度就够了」——轴只解释 0.8–1.8 % 的方差。

## 10 还缺什么 / 下一步

1. **v6 或 amend**：`covered_bp` 的偏移常量仍是在旧轴上拟合的。本报告证明现在改不改都不影响成绩，但「常量与硬件轴不匹配」这件事必须在冻结记录里说清楚，否则下一代读者会以为它们是当前轴的。
2. **28 天的功效问题没解**：P1 MAP 可声明是靠 MAP 的 sd 小（3.211），SBP 要半宽 2.55 需要约 38 天。这批只有 10 天。
3. **268–275 mmHg 仍零测量**：新轴在 255–265 段的证据来自 17 点里最高的三个点（262.4 / 264.9 / 264.85），再往上没有。要补测必须抬 `BP_MAX_PRESSURE_MMHG 280` 并重烧 hex。
4. **`legacy_firmware` 那 8 份现在用哪条轴**：它们的 `p` 是 2026-11-01 固件算的，标定不一定与今天相同。本报告对它们也施加了同一变换，这在物理上不一定成立——**这 8 份应当从任何轴重算的统计里排除**，本报告暂时保留它们只是为了「全库」那一栏对齐。
5. **P3 就在线边上**：新轴下 P3 SBP 跨天 −4.288、全库 −4.766。下一批如果补 P3，很可能是第一个被推过线的。
