# 更正：固件平滑窗不是缺陷，缩短它会更差

**这份文件更正我 2026-11-07 晚的判断。** 那份判断被写进了
`rebuilt_envelope_20261107.md`，并导致了"改固件平滑窗"的结论。**该结论是错的。**

## 一、我原来认为什么

我看到 `bp_algorithm.c:317-333`：

```c
/* 平滑包络：32 点窗口平均（800ms@40Hz） */
```

算出 32 点 @ 40 Hz = 800 ms，而心跳周期 750 ms，于是推断：方波均值滤波器的窗长
约等于信号周期时会抵消该分量，所以脉搏被固件削掉了。

**这个推断是错的。** 原因见第四节。

## 二、验证方法

导出的 `e` 是**逐点原始包络**，`s` 是 `e` 再做一次 32 点滑动平均的结果。所以
"换窗长"可以在离线精确复现，不需要改固件。

先确认复现正确：`moving_average(e, 32)` 与导出 `s` 的差值

```
max |mine - exported s| = 0.000000e+00
mean |difference|       = 0.000000e+00
```

**逐位一致**，所以这个离线实验是可信的。

## 三、结果：32 点是最好的，缩短会更差

用**冻结的估算器**（`tools/reference_bp.py`，逻辑完全不变），只替换它收到的包络序列：

| 包络序列 | MAP 均值/sd | SBP 均值/sd | DBP 均值/sd | ±10 内 M/S/D |
|---|---|---|---|---|
| **导出 s（32 点，现状）** | **+4.5 / 3.8** | **−0.2 / 10.0** | **+0.9 / 9.9** | **15/10/11** |
| e 平均 16 点 | +5.7 / 4.0 | −7.5 / 10.6 | +9.8 / 7.8 | 13/8/7 |
| e 平均 8 点 | +6.7 / 4.5 | **−23.4 / 12.4** | +18.3 / 4.7 | 7/2/0 |
| e 平均 4 点 | 估算器拒判 | — | — | 0/0/0 |
| e 平均 1 点（不平滑） | 估算器拒判 | — | — | 0/0/0 |

**窗长从 32 缩到 8，SBP 偏差从 −0.2 恶化到 −23.4，±10 内从 10/16 掉到 2/16。**
缩到 4 点以下，估算器直接判为噪声底。

**原代码注释里写的原因也是对的方向**：

```
32点(800ms)：成人量程漏气斜坡+阀冲击会激起 1-2s 瞬态振铃
800ms 平均把短时瞬态压到真实峰量级，真实 MAP 峰（持续 3-5s）保留
```

## 四、我错在哪

我把 `e` 当成了**带通信号**，于是套用"窗长≈周期会抵消该分量"。

但 `e` 不是原始振荡，它是**已经经过处理的量**：`extract_envelope_value()` 在 800 ms
窗口内做最小二乘直线拟合，返回 `|振荡 − 拟合直线|`——**这是整流后的结果**，不是载波。

对一个已整流的信号再取滑动平均，是**低通**，不是陷波。规整流已经被"搬"到了
基带，平均只会去掉纹波，不会抵消脉搏。

**所以"800 ms 窗 ≈ 750 ms 心跳周期 → 抵消"这条推理，前提就不成立。**

## 五、那之前的改善从哪来

`rebuilt_envelope_20261107.md` 报的改善（开发集 SBP sd 10.0 → 6.7）确实存在，但
**归因错了**。当时同时改了两件事：

1. 包络：固件 `s` → 逐搏峰峰值（`bp.capture` 的 `v` 带通后取峰峰）
2. 估算器：冻结逻辑 → 我自己的分箱中值 + 穿越搜索

把估算器固定为冻结版、只换包络，得到：

| 包络（同一个冻结估算器） | MAP 均值/sd | SBP 均值/sd | DBP 均值/sd | ±10 内 |
|---|---|---|---|---|
| 固件 `s` | +4.5 / 3.8 | **−0.2 / 10.0** | +0.9 / 9.9 | 15/10/11 |
| 逐搏峰峰值 | +8.6 / 4.3 | −4.8 / **7.2** | +7.7 / 7.4 | 11/12/10 |

**逐搏峰峰值确实让 SBP 的 sd 从 10.0 降到 7.2**（这一点成立），但 MAP 偏差从 +4.5
涨到 +8.6、DBP 从 +0.9 涨到 +7.7，±10 命中数在 MAP 上从 15 掉到 11。

**整体不是改善，是此消彼长。**

剩下那部分"改善"来自我自己的估算器，而那是在同一批开发集上设计的。**不能算数。**

## 六、结论

| 主张 | 状态 |
|---|---|
| 固件 32 点平滑窗是缺陷 | **错，撤回** |
| 缩短平滑窗能改善精度 | **错，实测更差** |
| 逐搏峰峰值包络能让 SBP sd 下降 | **成立**（10.0 → 7.2），但代价是 MAP/DBP 偏差变大 |
| 之前在开发集上把 SBP sd 做到 6.7 | 主要是自己估算器 + 调 DBP 比例的结果，**不能作为泛化性能** |

## 七、对"改固件重采"方案的影响

**用户选的 B 方案（改固件平滑窗 + 重采）的前提不成立，不应执行。**

改固件重采约需 2 小时，且会消耗掉"这批数据是同一固件下采集"的可比性。
在没有证据支持"改窗能变好"的情况下做这件事，是错误的。

如果仍要改固件，**唯一有依据的改动是把包络提取从"整流残差 + 平均"换成"逐搏峰峰值"**
——但那会让 SBP 变好、MAP 和 DBP 变差，**整体收益不明**，更需要先想清楚再动。

## 八、教训

**我在没有验证中间环节的情况下，用一条听起来很合理的信号处理推理，得出了一个错误结论，
并且已经据此给出了行动建议（花 2 小时改固件重采）。**

唯一挡住错误的是"先离线复现再动手"这一步。如果直接改固件再测，两次
（改前 32 点、改后 8 点）都要真实采 20 轮才能发现变差，代价约 4 小时。

**规则**：当结论指向"改硬件/改固件重采"这种高成本动作时，必须先在已存数据上
做可复现的离线验证，并且验证中间量（这里是 `s = ma(e, 32)` 逐位一致）。
