# 下一轮做什么：三条候选，推荐第一条

日期 2026-11-09。当前状态：容积 320 cc 已测、MAP 偏置已结案、数据集 67 份导出齐全、
40 轮前瞻已用尽。剩下三件有价值的事，按性价比排序。

## 推荐：用 BP Pump 2 的 RS-232 口拿到独立压力参考

这是**唯一**能把 `dataset_limitations.md` 第 1 条（最关键的那条）真正关掉的办法。

### 为什么它能解决根本问题

数据集里所有压力数字都来自同一颗 MPXV5050GP + 同一片 ADS1115。我们知道它读得稳
（25.0 ms 逐点无抖动）、知道它和面板一致到 ±0.9 mmHg —— 但"面板"也是我们在读，
不是独立记录。所以现在的表述只能是"自洽"，不能是"被独立核验过"。

BP Pump 2 前面板有一个 `Pressure Port`，内部有自己的压力传感器（手册 1-x：
"Pressure in the manifold is measured by a..."）。**把这个传感器的读数通过 RS-232
读出来，就得到了同一气路节点上的第二个物理测量**，而且是 ±(0.5% 读数 + 1 mmHg)
的仪器级读数。

### 手册已经给了完整命令表（Appendix D，`tmp/pdfs/opmanual_text.txt:3031-3302`）

| 命令 | 返回 | 用途 |
|---|---|---|
| `[GAUGE]` | ACK + 压力端口读数 + CR-LF | **每发一次读一次，这就是独立压力参考** |
| `[BP_VERSION]` | ACK + `2780201 Ver X.XX` | 确认固件版本 |
| `[BP_SERIAL]` | ACK + 序列号 | 写进 provenance |
| `[LEAK,XXX]` | ACK + 60 s 后泄漏率 | 已有面板读数，可交叉核对 |
| `[CUFF_EXT]` | ACK | 确保 External Cuff 模式 |
| `[SIM_STD120_80]` 等七个 | ACK | 用命令切预设，**消除"面板设定是声称值"这个缺口** |
| `[BLEED_SYSTEM]` | ACK | 收尾泄压 |

`[SIM_STD*]` 这一组特别重要：它能让你不用手按面板，而是用命令设预设，命令回显就是
证据。这直接补上 `panel_evidence_path: null` 的洞。

### 波特率与轮询可行性

手册（`:2685-2697`）：**固定 9600, 8N1, 无校验**。命令 `[GAUGE]\r` 约 8 字节，
回复约 8 字节，9600 baud 下往返线时约 2 ms，**10–20 Hz 轮询毫无压力**，
甚至能到 50 Hz。MCU 是 40 Hz，所以能拿到一条时间分辨率足够的独立轨迹。

### 需要什么

1. **一根 9M-9F 的 RS-232 直连线**（手册配件表 `:810` 就写 `RS-232 Serial Cable (9M-9F)`）
2. **一个 USB-RS232 转换器** —— **这台机器很可能已经有了**：注册表里
   `HKLM\HARDWARE\DEVICEMAP\SERIALCOMM` 与驱动库里有 FTDI `ftdibus.inf`/`ftdiport.inf`、
   `ser2pl_1.inf`、`silabser.inf`；此前枚举端口时还看到过 `COM12`（FTDI）
3. 一个轮询脚本（我可以写，约 100 行）

### 待查证（不确定就标出来，不凭经验）

- BP Pump 2 的 D-9 是 **female**（手册 `:601` "serial D-9 female connector"），PC 侧
  通常也是 male/female 混合，**是否需要 null modem（2-3、3-2 交叉）必须先查证**。
  Fluke 把 9M-9F 列为配件，但没说交叉/直通 —— **接线前先断电量通断，不要直接通电**。
- `[GAUGE]` 的更新率是"每次命令刷新"还是"内部固定刷新"，手册没说。需要实测：
  发两次命令看读数是否变化。
- 轮询会不会打断 BP Pump 2 正在进行的脉搏注入，手册没说。需要实测。

### 拿到之后能做什么

有了独立动态压力轨迹，四件事从"说不清"变成"能定量"：

1. **压力轴动态精度**：不再只有静态标定的 ±0.9 mmHg，而是全程逐点的残差分布
2. **320 cc 容积**：用两条独立压力轨迹各自算一遍，互相校验
3. **MAP 偏置**：现在只能说"面板 MAP 是算术注释、DINAMAP 也偏 +4"；有了独立轨迹
   就能算出**模拟器合成包络的真实峰位**，彻底闭环
4. **数据集性质升级**：从"自洽"变成"第三方仪器同步核验过"

## 第三：追 Preset 2 的 SBP −7.4 mmHg 系统低估

纯离线分析，不动硬件。现象：Preset 2 的 SBP 偏差均值 **−7.4**，但同一批的 MAP 偏差
是 **+4.4** —— 方向相反。说明该压力段 0.5 倍阈值穿越点系统性偏低。

已知可查的方向：
- 该段包络在 0.5 倍阈值附近是否有一段"平台"（`flat95` 类指标）
- 是否与 Preset 2 的脉搏容积 0.65 cc（最大档）导致的幅值非线性有关
- 与 Preset 1（SBP +0.8）的差别在哪一段压力

**注意**：40 轮前瞻已用尽，任何基于这批数据做的调整都不能再宣称是前瞻验证。

## 不建议

  已记录的、结构性障碍。参考实现 `tools/reference_bp.py` 已经绕开了；改固件只会让
  `PEAK_WINDOW_20261105` 这个已冻结的固件标识失去意义，而数据集的可复现性依赖它。
- **再采一批和现有 40 轮同条件的采集**：重复不产生新信息，只会让"前瞻已用尽"这条
  边界变得模糊。
