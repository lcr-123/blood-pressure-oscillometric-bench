# BP Pump 2 RS-232 链路打通了：`[GAUGE]` 能读，但只有 1 mmHg / 5 Hz

日期 2026-11-09。上一次尝试失败是因为适配器没插上（见 `rs232_attempt_20261109.md`）。
用户"刚插上"之后，**FTDI 适配器立刻枚举为 `COM12`**，协议一次就通。

## 一、链路证据

```
opened COM12 at 9600 8N1
[BP_VERSION]  -> ACK + '2780201 Ver 2.01S'
[BP_SERIAL]   -> ACK + '5788005'
```

- 适配器：`USB VID:PID=0403:6001 SER=BG04UQFT`，FTDI，驱动 `FTDIBUS`
- 手册说波特率固定 9600 8N1（`:2685-2697`），实测直接可用，**不需要交叉线**。
  这一条消除了之前"必须断电量 2-3 脚"的顾虑 —— 直通线就行。
- 固件 `2.01S`、序列号 `5788005`，应写入 provenance

## 二、`[GAUGE]` 的实测特性（手册没写，只能测）

### 原始帧

```
06 20 20 30 20 20 20 6d 6d 48 67 0d 0a
ACK   '  0   mmHg\r\n'
```

**整数，没有小数位。** 这对应手册里的"标准版分辨率 1 mmHg"，
而不是高精度版的 0.1 mmHg。所以：

- 分辨率 **1 mmHg**（量化台阶）
- 精度标称 ±(0.5% 读数 + 1) → 在 200 mmHg 处是 ±2 mmHg

这条对本项目的独立参考用途是**可接受的**：我们要判断的是"MCU 与面板是否差到
几十 mmHg"，不是 0.1 mmHg 级别的小数。

### 响应延迟 ≈ 170 ms

| 指标 | 值 |
|---|---|
| 中位延迟 | **172.9 ms** |
| p95 | 227.2 ms |
| 最大 | 510.5 ms |
| 可持续轮询率 | **5.0–5.2 Hz** |

9600 baud 传 13 字节只需 13 ms，所以这 170 ms 几乎全是 Tester 内部的处理时间。
**这是硬上限，不会因为改成 115200 而变快**（波特率是设备固定的）。

### 突发不丢帧

连发 60 条 `[GAUGE]` 不留间隔，12 秒内回 **ACK=60, NAK=0, 行=60**。
说明它有输入缓冲，不会丢命令 —— 但回复速度被内部处理节流在 5 Hz，
所以轮询脚本必须"发一条等一条"，不能发完不管。

## 三、这对"独立动态压力参考"意味着什么

| 项 | MCU（MPXV5050GP + ADS1115） | BP Pump 2 `[GAUGE]` |
|---|---|---|
| 采样率 | **40 Hz**（25 ms） | **5 Hz**（170 ms 延迟） |
| 分辨率 | 0.0142 mmHg | **1 mmHg** |
| 精度 | 静态标定 ±0.9 mmHg | ±(0.5% + 1) |
| 独立性 | 是 | **是（不同传感器、不同 ADC、不同固件）** |

**关键判断：5 Hz / 1 mmHg 不足以做逐点动态比对，但足够做"分层核验"。**

具体可做的：

1. **静态点核验**：在 100/150/200/240 mmHg 保压，各取 20 个 `[GAUGE]` 读数的中位数
   与 MCU 同段中位数比 —— 这直接关掉"两套传感器是否一致"这个洞
2. **慢变段核验**：放气 2–3 mmHg/s 时，5 Hz 采样对应每点 0.4–0.6 mmHg 的变化，
   在 1 mmHg 量化下仍有意义；可以给出**整轮的偏差分布**而不只是静态点
3. **不能做的**：逐搏波形比对（每搏 0.75 s，5 Hz 只有 3–4 个点）、包络细节比对

**所以 `dataset_limitations.md` 第 1 条可以改口径**：从"无独立动态压力参考"
改为"有 5 Hz / 1 mmHg 的独立静态与慢变参考，不足以核验逐搏波形"。
这是**实质性改善**，不是关门大吉，但比之前强得多。

## 四、当前阻塞：MCU 那一路串口掉了

在准备做压力比对测试时发现：

- `COM6`（`FAED:4870`，MCU 的 Horco CMSIS-DAP 复合设备）**已从 PnP 树消失**
  （`Present = False`），`SERIALCOMM` 注册表里只剩 `COM12`
- OmniProbe 进程还在（PID 9448），8765 仍在监听，但下发命令会被拒：
  `{'error': 'Serial port not connected', ...}`
- 推力测试因此全部失败

这不是软件问题 —— 插 RS-232 适配器时很可能把 MCU 的 USB 线碰掉了（或者共用一个
HUB 时挤掉了）。**需要把 MCU 的 USB 重新插上**，`COM6` 才会回来。

## 五、下一步（插回 MCU 之后）

1. 先确认 BP Pump 2 的 `Pressure Port` 是否有管子接到三通上 —— 为了做容积测量，
   之前把它从三通摘掉并堵口了。如果没接回去，`[GAUGE]` 会一直读 0
   （这也正是刚才所有读数都是 `0   mmHg` 的可能原因，**两种可能尚未分辨**：
   端口没接、或者回路本来就是 0 表压）
2. 跑 `python tmp\gauge_vs_mcu_20261109.py --port COM12 --target 100`：
   MCU 打到 100 mmHg 封阀，同时用 `[GAUGE]` 读它自己的压力端口。
   - 面板跟着读 ≈100 → 两个仪器共节点，可以做真比对
   - 面板一直是 0 → 端口没接，需要把管子接回三通
3. 共同节点确认后，做静态多点核验（100/150/200/240 mmHg），
   每点 20 个读数取中位数，写进 `data/reports/independent_reference_20261109.md`

## 七、修好的两个脚本缺陷

1. `open_bridge()` 要求传**文件对象**，不是路径字符串。传字符串会触发
   `AttributeError: 'str' object has no attribute 'write'`。
2. `bridge` 没有 `close()` 方法，要 `bridge.sock.close()`；
   `bridge.samples` 是**属性列表**（元素含 `timestamp`/`raw`/`ads`/`sensor`/`est`/`valid`），
   不是方法。

两条都已在 `tmp/gauge_vs_mcu_20261109.py` 里改对。
