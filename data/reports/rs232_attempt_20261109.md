# BP Pump 2 RS-232 直连：第一次尝试，适配器没有枚举

日期 2026-11-09。用户插上了 RS-232 相关线缆后要求试一下。结论：**电脑完全没有看到
任何新设备**，不是配置问题，是物理层没通。

## 一、观测到的事实

| 检查 | 结果 |
|---|---|
| pyserial `list_ports` | 只有 `COM6`（MCU 的 Horco CMSIS-DAP 复合设备） |
| PnP 树 class=Ports（含未连接） | `COM3`(ESP32, absent)、`COM4`/`COM5`(CH340, absent)、`COM12`(FTDI, absent)、`COM6`(present) |
| 暴力打开 COM1..COM30 | 除 COM6 外**全部 `FileNotFoundError`**，从未存在过 |
| `Win32_PnPEntity` 里 `^USB\` 的实例 | 15 个，全是摄像头/触摸板/蓝牙/MCU，**无新 VID/PID** |
| 有问题的设备（Error/Unknown 状态） | 只有 `ACPI\MSFT0001\1`（I2C HID，与本次无关） |
| `Kernel-PnP/Configuration` 近 3 小时事件 | **0 条** |
| `Kernel-PnP/Device Management` 最近记录 | 最新是 13:58（ESP32 拔出），插线之后无记录 |
| `setupapi.dev.log` 尾部 | 无本次安装记录 |
| 注册表 `Enum\USB` 里的串口芯片 | 只有历史设备：`VID_1A86&PID_7523`×2、`VID_0403&PID_6001`，**全部 absent** |
| `SERIALCOMM` 注册表键 | 只有 `COM6` |
| 强制 `pnputil /scan-devices` | `Access is denied`（无管理员权限，但不影响判断：连"未知设备"都没出现） |
| 设备安装限制策略 | `HKLM\SOFTWARE\Policies\...\DeviceInstall\Restrictions` **不存在**，没被策略拦 |

## 二、这排除了什么

- **不是驱动问题**：驱动库里有 FTDI（`ftdibus.inf`/`ftdiport.inf`）、`ser2pl_1.inf`、
  `silabser.inf`，即使插一个陌生芯片也至少会以"未知设备"出现在设备管理器里。
- **不是端口被占用**：占用的表现是 `PermissionError`（COM6 现在就是），而不是端口不存在。
- **不是设备安装策略拦截**：注册表里没有 Restrictions 键，`setupapi.dev.log` 里那些
  "Blocking Core Device Install" 都是 11-03 到 11-08 的旧记录，与本次无关。
- **不是 Windows 反应慢**：40 秒的热插拔监视（快照差分，2 s 粒度）里 CPU、摄像头、
  蓝牙、MCU 的 15 个 USB 实例一个没变。

## 三、剩下的可能（全部是物理层）

按可能性排序：

1. **线只插了 Tester 一头**。BP Pump 2 背面是 D-9 female（手册 `:601`），如果用的是
   裸 D9-D9 线，另一头必须接**电脑上的 D-9 口** —— 这台笔记本没有原生串口，
   所以必须有一个 USB-RS232 转换器在中间。只有 D9-D9 线是不会有任何反应的。
2. **USB 端插在扩展坞/显示器上，而那个口没上电或不通数据**。
3. **用的是充电线**（只有电源两芯）。这类线外观与数据线一样，接什么都没反应。
4. **转换器本身坏了**，或者是一个 TTL 电平的模块（CH340/CP2102 裸板）而不是
   真正的 RS-232 收发器 —— 后者即使插入也只会作为 USB 设备出现，但用户若只插了
   D9 那头，同样什么都不出现。

**判别方法**：插上后看设备管理器"端口(COM 和 LPT)"有没有新条目。有 → 是接线/协议问题；
没有 → 是物理层问题，与本项目软件无关。

## 四、如果买件，买什么

手册配件表（`:810`）列的是 `RS-232 Serial Cable (9M-9F)`。注意：

- Tester 侧是 **D-9 female**
- 转换器侧常见是 **D-9 male**
- 所以直连需要 **9M-9F 直通线**；但**是否需要交叉（null modem）手册没有说明**

**必须先断电量通断**：D-9 的 2、3 脚如果交叉（2-3、3-2），就是 null modem；
直通则是 2-2、3-3。在不知道的情况下通电，可能让两个输出对顶。

## 五、已准备好的工具

`tools/bp_pump2_remote.py`（已入库，py_compile 通过）：

```powershell
# 只列端口，并标出哪个是 MCU 链路（FAED:4870），避免误开
python tools\bp_pump2_remote.py --list

# 一旦出现新端口，用只读命令验证链路
python tools\bp_pump2_remote.py --port COM7
#   发 [BP_VERSION] → 期望 ACK(0x06) + "2780201 Ver X.XX" + CRLF
#   再发 [BP_SERIAL] → 序列号，记进 provenance
#   然后 [GAUGE] × N，验证读数刷新

# 连续读压力端口（成功后才有意义）
python tools\bp_pump2_remote.py --port COM7 --gauge 20 --interval 0.2
```

脚本**只发只读命令**（`[BP_VERSION]`、`[BP_SERIAL]`、`[GAUGE]`），不改 Tester 状态。
会把 MCU 的 `FAED:4870` 排除掉，不会朝固件乱发字节。

若 `[BP_VERSION]` 有 ACK 但数据乱码 → 波特率错（手册写死 9600，但值得用
`tmp/baud_scan_20261108.py` 的思路再扫一遍）；若完全无字节 → 接线问题；若 NAK →
端口上有东西在说话，但命令拼写或行尾不对。

## 六、这次尝试的价值

虽然没通，但证明了**软件侧已经就绪**：工具写好了、命令表从手册里挖出来了、端口识别
逻辑能区分 MCU 与 Tester 链路。剩下的是买对线。这条路的收益没有变：它是唯一能把
`dataset_limitations.md` 第 1 条（无独立动态压力参考）真正关掉的办法。
