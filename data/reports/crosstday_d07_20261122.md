## 2 一个 `raw=0` 的坏样本：ADS1115 读回全零，固件却报 `VALID`

### 2.1 现象

第一次漏率采集（`tmp/omniprobe/daily_leak_20261122.ndjson`，986 样本）在第 12:19:27.666 抓到：

```
12:19:27.623 [Pressure] raw=9147 ads=1143mV sensor=1578mV est=110.0mmHg VALID
12:19:27.666 [Pressure] raw=0    ads=0mV    sensor=0mV    est=0.0mmHg   VALID
12:19:27.726 [Pressure] raw=9116 ads=1140mV sensor=1572mV est=109.6mmHg VALID
12:19:27.726 [Deflate] VENT PB8=HIGH PC1=HIGH PC8=HIGH
```

管道守卫在 `tmp/direct_serial_bridge_20261107.py:161-162`（`tmp/bp_development_trial_20261031.py:84` 同一行）：

```python
if self.active and (valid != 'VALID' or int(raw) < 1000):
    raise RuntimeError('invalid calibration or extreme raw signal')
```

于是整个 60 s 窗口作废，`RESULT {... "outcome": "failed"}`。换名重测（`daily_leak_20261122b`）正常。

**全库范围**（`tmp/d7_lowraw_corpus_20261122.py`）：1180 份 ndjson，覆盖 16 天
（1101 11、1105 7、1106 18、1107 48、1109 4、1111 42、1112 127、1113 37、1114 112、
1115 75、1116 17、1117 29、1118 28、1119 32、1120 31、1121 29）→ **`files with raw<1000: 0`**。
今天是唯一一例。

### 2.2 为什么不是真实读数

前后两帧相隔 43 ms / 60 ms，压力在 110 mmHg 附近平滑下降（9147 → 9116）。
真实的传感器输出不可能在 43 ms 内从 1578 mV 跳到 0 mV 再跳回来。
所以这是一个**读数失败被当成有效值**的问题，不是信号本身。

### 2.3 固件侧机理

`blood pressure monitor/Core/Src/ads1115.c:145-159`：

```c
status = ADS1115_ReadRegister16(ADS1115_REG_CONVERSION, &conversion);
if (status != HAL_OK) return status;
*raw_value = (int16_t)conversion;
return HAL_OK;
```

只要 I2C 传输"成功"而转换寄存器读回 `0x0000`，`raw` 就是 0，函数返回 `HAL_OK`。
`ADS1115_ReadSample`（`:203-207`）只检查 `status`，不看数值：

```c
status = ADS1115_ReadRaw(&next.raw);
if (status != HAL_OK) { return status; }
next.ads_voltage_v = ADS1115_RawToVoltage(next.raw);   /* raw=0 → 0 V */
next.sensor_voltage_v = next.ads_voltage_v * ADS1115_DIVIDER_SCALE;
next.pressure_mmhg = BP_Cal_GetPressure_mmHg(next.sensor_voltage_v);
if (next.pressure_mmhg < 0.0f) { next.pressure_mmhg = 0.0f; }   /* :215-218 钳到 0 */
```

0 V 代入 `82.326 × 0 − 19.887 = −19.887 mmHg`，被 `:215-218` 钳成 0，
`main.c:461` 再无条件打 `BP_Control_IsCalibrationValid() ? "VALID" : "UNCAL"`：

```c
"[Pressure] raw=%d ads=%ldmV sensor=%ldmV est=%ld.%01ldmmHg %s\r\n",
...
BP_Control_IsCalibrationValid() ? "VALID" : "UNCAL"
```

`VALID` 描述的是**校准记录有效**，不是**这一帧读数有效**。两个语义在串口上用了同一个字。

### 2.4 与周边扰动的关系（同一窗口，但不是同一失败路径）

- `rx_errors` 在 12:16:51 是 0，12:18:38 已经是 **125**（`tmp/d7_rx_trace_20261122.py` 按 mtime 排）。
- 12:19:29.399（阀工作点开始后）出现 `[ADSdiag] stage=4 status=1 reg=0x01 err=0x00000200
  state=0x20 sr1=0x0000 sr2=0x0002 errors=2 recoveries=1` 与 `[ADSbus] cr1=0x0501 pb=0xFF3B scl=0 sda=0`。
- 12:25:45 的预跑复核读到 `[Fault] code=4 name=SENSOR_READ age=181201ms`、
  `errors=3 recoveries=3`。

**注意两者的区别**：`[ADSdiag] errors` 记的是 `ADS1115_Fail(...)` 走过的那条路
（`main.c:510` 分支，会打 `[Pressure] sample failed status=…; will retry init`）；
而 12:19:27.666 那一帧**没有** `sample failed` 行，说明它走的是 `HAL_OK` 分支，
**没有被任何故障计数器记到**。所以 `errors=2 → 3` 里不含这一帧。

至于同一窗口里 `rx_errors=125`（UART 侧）与 ADS1115 的 I2C 扰动是否同源，
仍然没有证据区分——`err=0x00000200` 对应 `HAL_I2C_ERROR_AF`（应答失败），
`pb=0xFF3B` 的 `scl=0 sda=0` 说明那一刻总线被拉着，
这与 UART 的 `rx_errors` 是两条完全独立的物理链路，**不应当默认同源**。

## 10 还缺什么

1. **`raw=0 VALID` 是否应该在固件里拒绝**——现在 `ADS1115_ReadRaw` 拿到 `conversion==0`
   就返回 `HAL_OK`，`ADS1115_ReadSample` 只查 status 不查数值，导致 0 V 被当成合法读数
   （再被钳成 0 mmHg 并标 `VALID`）。改成"读回全零视为失败"能消掉这一类坏样本，
   但**改固件 = 本批次从改动日终止**，只能在批次结束后做。
2. **`rx_errors=125` 的确切来源**——D3 533、D4 772→876、D5 462→514、D6 0、D7 125。
   今天能确定它产生在 12:16:51–12:18:38 之间（开机检查到第一次漏率采集之间），
   但那一分钟里只有 `zero_sanity` 与 `leak` 两条命令，没有高负载写入，
   是 USB-serial 侧还是 MCU 侧溢出仍未区分。
3. **I2C 的 `err=0x00000200`（AF 应答失败）与 UART 的 `rx_errors` 是否同源**——
   `pb=0xFF3B` 时 `scl=0 sda=0` 说明总线被拉住，这是电气层现象，与 UART 无关；
   但两者在同一个时间窗口里出现，可能是同一个电源扰动。**不应默认同源，也不应默认无关。**
4. **漏率与阀 flow 同时大降是否同源**——今天漏率稳定段 −11.13 → −9.25（−17 %），
   flow 0.32042 → 0.17630（−45 %）。两者都是气路量，但一个是泄漏、一个是脉冲放电，
   物理上未必同因。D8 若继续同向下降，就可以谈"气路整体变紧/变松"。
5. **日志命名撞名的修法**——`tmp/run_crosstday_20261116.py:209` 加块字母即可，
   但改冻结脚本会让批次从改动日终止，**批次结束后第一件事**。
6. **`profile normal` 复位失败的长期影响**——今天 8/28 失败，比昨天 22/28 好，
   但失败的 8 轮收尾零点仍在 +0.8…+1.6。若某天全部失败，次晨开机会是 `peak`，
   那时必须走 D7 卡片里记的"profile 探针先读回"流程，不能假设是 normal。
7. **P4 档的陡斜率离群**——D4、D5、D6、D7 四天累计 6 次，全部落在 P4。
   今天块A 的 P4（−2.63）陡、块B 的 P4（−2.00 / −1.96）不陡，
   说明 P4 只是"更容易"，不是"必然"。
