# `[GAUGE]` 命令会把 Tester 切出 Standard BP 模式

日期 2026-11-09。这是今天最重要的一条操作约束，而且是靠用户三次观察才定下来的。

## 一、证据链

| 时间 | 我做了什么 | 用户看到的屏幕 |
|---|---|---|
| 16:45 | 起了 `gauge_logger`，每 0.5 s 发 `[GAUGE]`，共 214 次 | — |
| 16:49 | 又发 4 次 `[GAUGE]`（`bp_pump2_remote.py --gauge 4`） | "还是 gauge" |
| 16:52 | 用户在面板上按回 **Standard BP**，确认 `255/ 195 (215)`、`80 BPM`、`0.55 cc`、`Cuff: External` | Preset 4 ✓ |
| 16:54–16:58 | 采集脚本因桥接会话失效在 `version` 处退出，**未向 MCU 发任何命令** | （未变） |
| 17:00 | 跑 `gauge_vs_mcu2_20261109.py --target 100`（持续轮询 `[GAUGE]`） | — |
| 17:03 | 又发 3 次 `[GAUGE]` | **"你又调到了 static measure 模式了"** |

中间**没有任何其他面向 Tester 的命令**。所以结论是唯一的：

> **`[GAUGE]` 会让 Tester 跳到 `PRESSURE TESTS → STATIC PRESSURE → GAUGE` 屏，
> 从而离开 Standard BP 模拟模式。**

手册 Appendix D（`:3262-3271`）只写了 `[GAUGE]` "Returns ACK then pressure port value"，
**没有说它会导航 UI**。这是实测发现的，不是手册写的。

## 二、为什么这条很要紧

Standard BP 模式下，脉搏注入是**那个屏幕上的模拟在跑**。屏幕被切到 Pressure Gauge，
模拟就结束了 —— 换句话说：

- **RS-232 独立压力参考，和 Standard BP 采集，不能同时进行。**
- 任何"边采集边记 `[GAUGE]`"的数据，里面根本没有脉搏。

这也解释了为什么今天上午那个 214 点的 gauge 日志全是 `0.0` —— 那段时间回路本来在
环境压力，读 0 是对的，但它同时把面板顶出了 GAUGE 屏之外的位置。

## 三、已确认可以做的事

`[GAUGE]` 在**不需要脉搏**的场合完全可用，而且今天已经验证有效：

| 用途 | 状态 |
|---|---|
| 共节点确认（`--target 150`，封阀保压） | ✓ 通过，稳定段差 −1.3…−2.6 mmHg |
| 双传感器泄漏测试（120 s 封阀保压） | ✓ 通过，斜率差 3.2% |
| 静态点核验（不打脉搏） | ✓ 可用 |
| **Standard BP 采集期间记录** | ✗ **禁止**，会把模拟切掉 |

## 四、100 mmHg 复查（今天第二次共节点验证）

TC 之前那次传感器异常期间做的，结果意外地干净：

| 时刻 | MCU | Tester | 差 |
|---|---|---|---|
| +1 s | 92.00 | 20.00 | −72.00（刷新滞后，必丢） |
| +2 s | 89.10 | 79.50 | −9.60 |
| +3 s | 87.65 | 87.50 | −0.15 |
| +5 s | 85.80 | 85.50 | −0.30 |
| +8 s | 84.00 | 84.00 | **0.00** |

**终点偏差 −0.25 mmHg**，比 150 mmHg 那次的 −4.1 好得多。说明两仪器的一致性随压力
变化，或者 150 那次含未散尽的瞬态。**两条都要留着，不能只报好看的那个。**

## 五、顺带排除的一个误判

17:00 前后 MCU 报出的真实压力一度是 **−9.02 / −8.94 / −6.8 … −5.97 mmHg**
（`sensor` 130 → 169 mV，标定零点 242 mV）。

我一度怀疑是传感电路出了问题。**但随后它自己恢复了**：

| 时刻 | sensor | 推算真实压力 |
|---|---|---|
| 17:00 | 130 mV | −9.02 |
| 17:02 | 149 mV | −7.6 |
| 17:04 | 161 mV | −6.6 |
| 17:06 | 245 mV | **+0.3** |

而 11-07 那次 MCU 复位（`112327`）的取证记录同样显示：复位前 `sensor` 最低到
**129 mV**，然后复位。**两次都是 129–169 mV 区间，然后恢复。**

这不像坏件，更像**供电跌落**：MPXV5050GP 是比率式输出
（`VOUT = VS × (P_kPa × 0.018 + 0.04)`），零点 242 mV 对应 VS = 5.0 V；
若 VS 掉到 3.3 V，零点就是 160 mV —— 正是我们看到的数。

**如果真的是 VS 跌落，后果很严重**：MCU 的换算仍按 5.0 V 的斜率，所以读数会被压缩。
按 3.3 V 算，MCU 显示 150 mmHg 时真实压力是 **237.5 mmHg**（比它高 58%）。

**但这次没有发生**：传感器恢复后 245 mV，且 100 mmHg 下与 Tester 一致到 0.25 mmHg。
所以要么跌落只发生在**未加压的静态段**（此时没有压力读数需求），要么它是短暂的。

**仍未定因，记为开放项。** 下次出现时立刻用 `[GAUGE]` 对比加压读数，就能判定是
"零点漂移"还是"增益压缩"——两者的区别是后者在高压下偏差更大。

## 六、操作规则（从今天起）

1. **采集 Standard BP 数据时，绝对不发 `[GAUGE]`**，也不跑任何会发它的脚本。
2. 需要独立参考时，**单独跑一轮静态/保压验证**，此时面板停在 GAUGE 屏是正常的、也是必需的。
3. 采集脚本里**不得**内置 gauge 记录（我今天的做法错了，已回退）。
4. 每轮采集前确认面板在 Standard BP 且三个数字对，采集开始后不碰 Tester。
