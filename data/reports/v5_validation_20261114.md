# v5 前瞻验证：一套常量通吃七档的估计器没有通过预注册验收（2026-11-14）

## 0. 一句话结论

`data/protocols/reference_bp_freeze_v5_candidate.md` 事前写死了五条验收标准（C1–C5）。在 2026-11-14
新采的 **71 轮**前瞻批次上：

| 判据 | 要求 | 实测 | 结果 |
|---|---|---|---|
| C1 精度 | 三项池化 sd ≤ 8.0 且 \|mean\| ≤ 5.0 | MAP +0.21/**11.60**、SBP +2.23/**11.17**、DBP +2.94/**12.96** | **FAIL** |
| C2 比 v2 好 | 交集上三项 sd 各低 ≥ 1.0 | MAP 11.79 → **11.94（涨 0.15）**；SBP 36.88 → 11.22；DBP 14.85 → 13.35 | **FAIL**（只卡在 MAP） |
| C3 均值不恶化 | \|mean\| 不比 v2 差 > 1.0 | MAP +4.03 → +0.37；SBP +13.79 → +2.81；DBP +3.41 → +3.09 | PASS |
| C4 出数率 | ≥ 0.80 | **51/71 = 0.718** | **FAIL** |
| C5 无静默大错 | 已发布轮任一项 > 20 mmHg 的数量 = 0 | **2 轮** | **FAIL** |

**`v5 FAILS: C1_accuracy, C2_sd_lower_than_v2, C4_publish_rate, C5_no_silent_blunder`。**
按预注册 §3 的判定规则，数据集继续以冻结 v2 作为参考算法输出，并在每次引用时注明它是
**0/7 档达标、有 18 轮静默 >20**。`data/reports/covered_algorithm_20261113.md` 里"不能写"的第 1、2
条继续有效。

这份报告的全部价值在于：**同样的规则在开发语料上 7/7 档全过、静默 0，在真正前瞻的 71 轮上
1/5 条判据通过**。这正是当初要预注册的理由。

## 2. C1/C2/C3 的判分与同批 v2 对照

同一个 71 轮批次上，两个估计器的池化结果（各自已发布的轮，分母不同，**只用于描述**）：

| | 冻结 v2 | v5 |
|---|---|---|
| 发布 | 62/71 | 51/71 |
| MAP | +3.23 / 10.76 fail | +0.21 / 11.60 fail |
| SBP | +8.94 / 34.26 fail | +2.23 / 11.17 fail |
| DBP | +4.94 / 13.97 fail | +2.94 / 12.96 fail |

C2/C3 必须在**两边都发布的 48 轮交集**上算（否则候选人可以靠多拒判"赢"）：

| 量 | v2 均值/sd | v5 均值/sd | sd 变化 | 逐轮更近/更远/不变 |
|---|---|---|---|---|
| MAP | +4.03 / 11.79 | +0.37 / 11.94 | **+0.15 → FAIL** | 9 / 18 / 21 |
| SBP | +13.79 / 36.88 | +2.81 / 11.22 | −25.66 → PASS | 14 / 1 / 33 |
| DBP | +3.41 / 14.85 | +3.09 / 13.35 | −1.50 → PASS | 7 / 0 / 41 |

**这是本轮最重要的一张表。** v5 在 SBP 上确实把 v2 从 sd 36.88 救到 11.22（v2 在这批里给出过
`SBP = +55.95` 均值的 P5 结果），DBP 也小胜；**唯独 MAP 没赢，还微涨 0.15**。所以 C2 失败不是
"整体没改善"，是"三个量里有一个没改善，而预注册要求三个都改善"。这个失败**不能靠解释绕开**，
预注册写死"任一条不过即否决"。

C3 通过：三个量的均值都没比 v2 差（MAP 从 +4.03 到 +0.37，SBP 从 +13.79 到 +2.81）。

长尾（v5 已发布的 51 轮）：

|---|---|---|---|---|---|---|

| SBP | 5.03 | 8 | 3 | **2** | **50.85** | 同上 |

## 3. 失败集中在哪：把批次按台架状态切成两半

采集过程中台架出过一次状态变化（§4 给出物理证据），切分点在 **12:16**：

| 半边 | 轮数 | 发布 | silent>20 | MAP | SBP | DBP |
|---|---|---|---|---|---|---|
| 早半段 < 12:16（P1 + P2） | 21 | 18 | **2** | +5.03 / **18.25** fail | +3.77 / **16.58** fail | +9.35 / **20.30** fail |
| 晚半段 ≥ 12:16（P3–P7） | 50 | 33 | **0** | **−2.41 / 3.61 PASS** | **+1.40 / 6.86 PASS** | **−0.56 / 2.82 PASS** |

晚半段的三项全过 AAMI，而且配对 30 轮上 SBP 从 v2 的 `+19.54/44.04` 变成 `+2.24/6.48`。
**但这里有一条必须说清楚的限制：12:16 正好就是 Preset 3 的切换时刻**（切换日志
`tmp/omniprobe/preset_sweep_p3_switch.out` 的写入时间 12:16:28）。所以"分半"与"分档"完全重合，
**晚半段的漂亮数字可能来自"这几档本来就更容易"而不是"这批台架状态更好"**。两者这批数据分不开，
不能拿晚半段当 v5 有效的证据，只能作为"失败不是普适的"这一观察。

早半段的失败有两个来源：P2 的**两轮面板未确立的轮次**（§5，占掉 C1 与 C5），以及 11:49–11:54
那段零点故障造成的 27 次无导出尝试（这些轮根本不在批次里、不参与判分，但它们说明早半段的采集
条件不稳定；同期 P1 还有 3 次充气超时）。

## 4. 台架在 12:0x 变了什么（物理证据）

判分之外的另一件事：**从 12:09 起，每开阀毫秒放掉的气比之前多约 50%**。用"窗口内总压降 ÷ 总开阀
毫秒"的积分法（`tmp/integrated_valve_flow_20261114.py`，单周期压降不可测，见
`tmp/valve_cycle_walk_20261114.py`：脉宽 1–5 ms 远短于 25 ms 采样周期）：

| 预设 | 历史（mmHg / 开阀 ms） | 当日 <12:16 | 当日 ≥12:16 | 比值 |
|---|---|---|---|---|
| P1 | 0.0847 (n=78) | 0.0993 (n=11) | — | 1.17 |
| P2 | 0.0944 (n=23) | 0.1005 (n=10) | — | 1.06 |
| P3 | 0.0868 (n=22) | — | **0.1366 (n=10)** | **1.57** |
| P4 | 0.0980 (n=64) | — | **0.1469 (n=10)** | **1.50** |
| P5 | 0.0900 (n=11) | — | **0.1357 (n=10)** | **1.51** |
| P6 | 0.1058 (n=10) | — | 0.1364 (n=10) | 1.29 |
| P7 | 0.1225 (n=11) | — | ~0.13 | ≈1.1 |

配套变化：阀脉宽中位从 4 ms 掉到 3 ms（`tmp/valve_width_by_date_20261114.py`；当日峰窗脉宽直方图
`1:4, 2:264, 3:2624, 4:2897, 5:79`，历史 11-12 是 `1:8, 2:121, 3:1375, 4:5947, 5:2309, 6:203`），
峰窗放气速率中位从 1.89 涨到 2.23 mmHg/s。逐轮序列显示这是**两级台阶而不是缓慢漂移**：
P1 内部 10:39 从 0.085–0.093 跳到 0.099，`114316`（11:43）仍是最低的 0.0838，`120952`（12:09）
跳到 0.1414 —— 跳变发生在我 12:0x 做零点/负计数诊断、反复插拔气路的那段时间窗里。

**已排除的三个解释**（都做过定量检验）：

1. **闭环撞 1 ms 下限饱和** —— 脉宽 1 ms 的占比 0.1%（4/5868），还有 3→2 的余量，不成立。
2. **窗内模拟脉搏污染闭环的单点采样** —— 全库 277 轮相关系数 r = +0.132，P4 单独 74 轮 r = −0.045，
   不成立。
3. **闭合期漏气变大** —— 闭合段斜率多数日期本身就接近 0 甚至为正（压降几乎都发生在开阀瞬间），
   这个量噪声太大，只能当弱证据，不能支持"漏气变大"。

**未排除**：阀驱动有效电压/线圈温升导致开度变大；袖带或气室在反复插拔中位置改变；ADS 采样相位
相对阀脉冲的时序变化。**这些都需要人动手查线，脚本判不出来。**

这件事对本批判分的影响：它解释了"为什么晚半段的放气速率是 2.2–2.8 而历史是 1.6–2.6"，
也解释了为什么 P3/P4 的 `pulse_pressure` 门限拒判特别多（见 §6）。**但要说清楚：它不是 v5 被否决的
唯一原因，也不能拿它替 v5 开脱。** C2 的 MAP 一项在两个半边都没有改善（早半段 sd 18.07 → 18.25，
晚半段 3.34 → 3.78），所以即使把台架状态变化完全排除，C2 依然不过；而 C1 与 C5 的失败则确实
集中在早半段（§3、§5）。

## 5. 两轮"面板未确立"的处置（必须单独论证）

`120952` 与 `121253` 是 12:0x 台架故障后用**裸调用** `python tmp\run_v4_batch.py 2 2 v5_p2b` 补采的。
`tmp/run_v4_batch.py` **不发 `[SIM_STD*]`**，而 `tmp/run_preset_sweep_20261113.py` 是每档先发
`[SIM_STD*]` 并要求 ACK 才采。所以这两轮元数据里的 `panel_preset=2` 是**沿用上一批的假设**，
不是这两轮开始前重新确立的事实。

证据（`tmp/preset_shape_match_20261114.py`）：用每档的归一化脉搏带幅度剖面做最近邻分类，全库
**268 份里 262 份（97.8%）命中本档**；`120952` 到各档剖面的距离是
`p1 0.428 / p2 0.336 / p3 0.108 / p4 0.312 / p5 0.324 / p6 0.380 / p7 0.392`，
`121253` 是 `0.493 / 0.400 / 0.114 / 0.324 / 0.382 / 0.441 / 0.455` —— **两轮都最像 Preset 3**，
而且与当日真实的 P3 轮（`121628` 距离 0.095）几乎无法区分。它们的脉搏带峰值在 165–183 mmHg，
170–210 段的振荡主频 77–87 BPM（落在面板心率上，是脉搏不是毛刺）。

**处置**：预注册 §4 第 7 条禁止"因为某轮答案与面板不符而排除它"，所以这两轮**留在批次里**
（判分口径 A）。但报告必须同时给出敏感性口径 B：

| 口径 | 轮数 | 发布 | silent | C1（MAP/SBP/DBP） | C2 MAP | C4 |
|---|---|---|---|---|---|---|
| A 整批（预注册） | 71 | 51 (0.718) | 2 | +0.21/11.60 f、+2.23/11.17 f、+2.94/12.96 f | 11.79 → 11.94 **f** | 0.718 **f** |
| B 去掉这两轮（仅供敏感性） | 69 | 49 (0.710) | 0 | **−1.95/4.18 P、+0.43/6.65 P、+0.43/3.38 P** | 4.10 → 4.31 **f** | 0.710 **f** |

**结论：v5 的否决不依赖这两轮的处置。** 即使把最有争议的两轮全部拿掉，C2（MAP）与 C4 仍然 FAIL。
这两轮只影响 C1 与 C5 的呈现：整批看起来三项 sd 11–13，剔掉后是 3.4–6.7。
口径 B **不得**被写成判分结果，它只是说明"失败有多依赖这两轮"。

顺带一个必须记下来的教训：**补采脚本不重发 `[SIM_STD*]`，就可能在错误的面板状态下采集**。
正确的做法是任何采集都必须先确立面板，哪怕只补两轮。

## 6. C4 为什么塌：门限在这批上判错的比例远高于开发语料

`tmp/v5_refusal_audit_20261114.py` 对 20 次拒判做审计：把两道门限去掉，用同样三视图中位 + 两个
偏移算出"如果不拒会报什么"，再按最坏误差分类。

| 分类 | 判据 | 这批（20 次） | 开发语料（`covered_algorithm_20261113.md` §10，30 次） |
|---|---|---|---|
| `saved` | 不拒会错 > 20 mmHg | **2** | 24（那里叫 saved a bad answer） |
| `between` | 不拒会错 10–20 mmHg | 11 | 未单列 |
| `cost` | 不拒会错 ≤ 10 mmHg | **5** | 4（那里叫 false alarm） |
| `no_views` | 一个视图都没发布 | 2 | 0 |
| `genuine disagreement` | 三视图彼此差 10 以上 | 未单列 | 2 |

两批的分类口径不完全一致（开发语料用的是"视图间分歧"而不是"去门限后的误差幅度"），所以只能对
`saved` 与 `cost` 两行做比较：**开发语料 30 次拒判里 24 次救命、4 次误伤；这批 20 次里只有 2 次救命、
5 次误伤、11 次打平。**

明细（`误差 MAP / SBP / DBP`，单位 mmHg）：

- `saved`：`122551`（+7.4 / −10.2 / **+20.4**）、`123209`（−5.9 / **−21.9** / +2.3）—— 这两次拒判是对的。
- `cost`：`111849`（−5.0/+6.8/+4.7）、`112222`（−6.3/+6.5/+4.7）、`114316`（−7.6/+9.3/+5.9）、
  `124151`（−9.0/+8.9/+0.3）、`130703`（−7.7/−1.7/+4.9）—— 这五次拒判丢掉了可用的轮。
- `between`：11 份，最坏误差落在 10–20 之间，两种说法都站得住，例如 `131626`（+0.0/−19.6/+19.2）、
  `130351`（−3.7/−18.5/+12.0）。

**开发语料上 30 次拒判里 24 次救命、4 次误伤；这批 20 次里只有 2 次救命、5 次误伤、11 次打平**
（两批分类口径不完全一致，见上表注）。原因不是门限写坏了，而是这批数据里"错误幅度分布"与开发语料
不同：晚半段放气更快，P3/P4 的 `pulse_pressure` 余量掉到 1–7 mmHg（开发语料同档中位余量 16.2 / 13.6），
于是门限要么刚好卡住正确的轮，要么刚好放过错误的轮。这直接解释了 P3 只出 4/10、P4 只出 2/10。

**重要**：这不构成修改门限的理由。按预注册 §7 第 1 条，本批数据不得用来重选带宽/平滑/门限/偏移
中的任何一个。如果后续想改，必须**另写一份预注册**、另采一批数据。

## 7. 这一批证明了什么、没证明什么

**证明了**：

1. **预注册机制有效**。同一套规则在开发 222 轮上 7/7 档全过、静默 0；在 71 轮前瞻数据上只有
   C3 通过。若没有预注册，"7/7 档全过"会变成一个错误的结论。
2. **三视图融合对 SBP 的改善是真的**：交集 48 轮上 sd 36.88 → 11.22，逐轮更近 14 / 更远 1。
   v2 在这批数据上确实会给出 `SBP` 均值 +55.95 这种结果（P5 9 轮），v5 不会。
3. **MAP 没有改善**：交集上 sd 11.79 → 11.94（涨 0.15），逐轮更近 9 / 更远 18。这是 C2 失败的直接原因，
   也是最需要继续研究的一点——v5 的 MAP 偏移（−5.31）是在开发集上拟合的，在这批数据上把
   MAP 均值从 +4.03 拉到 +0.37，但没有降低分散度。
4. **拒判门限的行为依赖数据分布**，不是常数性质。同一套 0.15 / 10 mmHg 在开发语料上 24/30 救命，
   在这批上 2/20 救命。

**没有证明**：

1. **没有证明 v5 不行、也没有证明 v2 更好**。v2 在这个批次上更差（三项全 fail，SBP sd 34.26），
   预注册的意义只是"v5 不能取代 v2"，不是"v2 够用"。
2. **晚半段三项全过不等于 v5 在高档有效**，因为分半与分档在时间上完全重合（§3）。
3. **没有定位台架 12:0x 那个状态变化**（§4）。它是这批数据的采集条件，不是估算器性质。
4. **没有测 268–275 mmHg**、没有做温漂/迟滞、没有人体数据。这些边界与既往一致。
