## 三、设备侧仍旧失败（已知、非新问题）

```
[BP] calculation failed
[DBGFAIL] n=3417 map=2324(95.4) sbp=1(260.3) dbp=1(93.2)
```

固件把 MAP 搜索窗写死在 80–100 mmHg（`bp_algorithm.c:534-541`），而 Preset 4 的
MAP 是 215，所以它必然在 80–100 段里找到 95.4 这个点，然后把 SBP 判成 260.3
（超过 250 上限）、DBP 判成 93.2（大于 MAP，矛盾）→ 整轮作废。

**这是结构性障碍，不是本轮的问题。** 参考实现 `tools/reference_bp.py` 用全量程
搜索，绕开了它。详见 `data/reports/dataset_limitations.md` 第 4 条。

## 四、`profile normal` 恢复失败（本轮唯一流程缺陷）

```
[Profile] rejected: require inactive sealed fresh calibrated zero
[Profile] rejected: require inactive sealed fresh calibrated zero
```

收尾阶段封阀零点还没落到 ±1 mmHg 内就发了 `profile normal`，被拒。
**不影响数据**：`outcome = export_received`、导出完整、`target_restored_mmhg = 50`
成功。Profile 留在 `peak` 模式，下一轮脚本会先查询再决定是否设置，不会重复。

历史同一现象出现过多次（`135004`/`135527`/`142358`），根因是
`DeflateProfile_Set`（`main.c:281-289`）要求最后一次采样在 −1.0…+1.0 mmHg，
而封阀瞬间读数会先冲到 1–2 再回落。

## 五、与 340 cc 口径的对照

数据集工况容积 ≈ 340 cc，Preset 4 的 dV = 0.55 cc：

- 等温预测 dP = 975 × 0.55 / 340 = **1.58 mmHg**
- 绝热预测 dP = 1.4 × 1.58 = **2.21 mmHg**
- 本轮实测包络峰 30.27 mV，按 82.326 mmHg/V 换算 = **2.49 mmHg**

2.49 比绝热预测 2.21 高 **13%**，落在"面板标称 dV 可能偏低 10–36%"的已知区间内
（`data/reports/volume_crosscheck_20261109.md`）。**这是一致的，不是矛盾。**
