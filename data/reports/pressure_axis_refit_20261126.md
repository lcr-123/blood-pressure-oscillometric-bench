# 压力轴重标定（2026-11-26）：两参数修正、改前改后实测、以及它对已发表数字的影响

## 0 一句话

压力轴原来的误差是一条**线性斜坡**（−0.97 %/100 mmHg，17 点静态交叉验证 R² 0.7888），
所以不需要改固件数学、不需要重烧 hex —— **一条 `cal write 81.529 -20.03` 就把最坏总误差
从 5.715 mmHg 降到 2.840 mmHg，17/17 点全部落进 BP Pump 2 自身规格**。今天用三组独立
静态点（12 个测量窗口、压力 28.8–241.9）改前改后各测一遍：改前 2/4 落在规格内（最坏 4.52），
改后 **8/8 落在规格内（最坏 2.61）**。代价必须写清楚：**AAMI 七档从 6/7 掉到 5/7**
（P4 SBP 由"过"翻成"不过"），因为原来那 6/7 里有一部分是旧轴的 +3 mmHg 系统偏移凑出来的。

## 1 为什么修

### 1.1 已有的定量结论

`data/reports/pressure_axis_accuracy_20261111.md` 用 17 点静态交叉验证（34.0–264.85 mmHg，
`--settle-min 8 --max-drift 0.3`）量化过这条轴：

| 口径 | 斜率 | 截距 | R² | 残差 max | 落规格内 | 最坏总误差 |
|---|---|---|---|---|---|---|
| 中位数 | −0.9686 %/100 mmHg（SE 0.1294，95 % CI ±0.2536） | −0.3368 mmHg | 0.7888 | 0.772 | **8/17** | **5.715 mmHg** |
| 逐窗口差均值 | −0.8696 %/100（SE 0.1453） | −0.5270 | 0.7049 | 0.670 | 8/17 | 5.715 mmHg |

17 个差值（`tester − mcu`）全部为负，从 −1.0 单调走到 −3.42：

```
-1.0 -0.8 -1.3 -1.3 -1.7 -2.1 -2.0 -1.6 -2.7 -1.9 -2.7 -2.7 -2.3 -3.3 -3.0 -3.42 -2.85
```

**这是一条斜坡，不是一个噪声。** 斜率显著性 `p < 0.001`（SE 0.1294 对斜率 −0.9686），
R² 0.79 说明它解释了 79 % 的差值方差。

### 1.2 斜坡的代价

- 在 100 mmHg 处偏低 **1.31**，150 处 **1.79**，200 处 **2.27**，250 处 **2.76**，264.9 处 **2.90**。
- BP Pump 2 自身规格是 `±(0.5 % 读数 + 1) mmHg`：在 250 mmHg 处是 ±2.25，而我们的差是 −2.76
  → **超出参考仪器能做证的区间**，所以「压力轴准不准」这件事在 200 mmHg 以上无法自证。
- ISO 81060-2 对静态压力示值要 ±3 mmHg。旧轴最坏 5.71 mmHg，**从原理上就不满足**，
  这也是 `data/reports/dataset_limitations.md` 里那条限制的来历。

### 1.3 不是传感器非线性

`pressure_axis_accuracy_20261111.md` §4 已经算出：加二次项对残差没有帮助
（`F(1,14) = 3.08`，不显著；最坏总误差 2.836 → 2.762，只挪 0.07）。**两参数就够**，
说明偏差来自「一个固定的刻度误差 + 一个固定的零点误差」，不是曲线形状问题。

## 2 修法

### 2.1 换算

设旧轴把传感器电压 `v` 映射成 `p_old = 82.326·v − 19.887`，实测差值是
`diff = tester − mcu = a + b·mcu`（`a = −0.3368`、`b = −0.009686`）。
要让 `p_new = tester`，需要

```
p_new = (1 + b)·p_old + a
```

对应到固件的两个参数：

```
slope_new     = 82.326 × (1 + b)      = 81.5286
intercept_new = (−19.887 + a) × (1+b) = −20.0279
```

**注意截距也要乘 `(1+b)`** —— 我第一版漏了这一步，算出 `−20.2238`，会让 250 mmHg 处再偏 0.2 mmHg。

实际写进固件的是四舍五入后的 `81.529 / -20.03`（固件用 `%f` 解析，读回显示就是这个精度）。

### 2.2 固件侧必须先擦再写（本日发现的真实缺陷）

`blood pressure monitor/Core/Src/bp_cal.c:137` 的 `BP_Cal_Write()` **只调
`BP_Cal_FlashProgram()`，从不 `BP_Cal_FlashErasePage()`**；擦除只发生在 `:158`
`BP_Cal_Clear()` 里。STM32 的 Flash 只能把 1 写成 0，所以**改写成不同值时 `cal write`
必然失败**，返回 `[Cal] write FAILED (bad values or flash error)`，旧记录原样保留。

正确顺序：

```
cal clear      -> [Cal] cleared; pressure now UNCAL
cal write 81.529 -20.03
               -> [Cal] written+verified slope=81.529 intercept=-20.03 -> VALID
```

读回：`[Cal] VALID slope=81.529mmHg/V intercept=-20.03mmHg zero=0.246V sens=0.0920V/kPa`。

**这个缺陷值得单独修**：`BP_Cal_Write()` 应该自己先擦页，否则任何"改标定"的操作都会
静默失败一次、让人以为写进去了。修它要改固件 = 换 hex，本批次已收尾，放到下一批之前做。

### 2.3 不动的东西

- **不重烧 hex**：`cal write` 是运行时命令（`main.c:1304` `strncmp(..., "cal write ", 10U)`
  → `:1760` `sscanf(command_buffer + 10, "%f %f", &slope, &intercept)` → `:1764` `BP_Cal_Write`），
  冻结五件套哈希不变。
- **不动冻结常量**：`tools/validity_v2.py` 的 4.0 mmHg/s、`tools/reference_bp.py`、
  三份 freeze JSON 全部未改（`python tools/verify_freeze.py` 仍 `3 freeze record(s) intact`）。
- **不改 `tools/covered_bp.py` 的九个常量**（`MAP_OFFSET_MMHG -5.31` / `DBP_OFFSET_MMHG -1.16`
  等）—— 那是 v5 候选冻结的内容，本轮只做诊断，改动需要出 v6 或 amend。

## 6 对已发表数字的影响

### 6.1 AAMI 七档：6/7 → 5/7

用 `tools/covered_bp.py` 同一套三视图中位逻辑，只把压力序列换轴、偏移两种组合重算
（`tmp\axis_rescore3_20261125.py`，265 轮里 235 轮双轴都可发布）：

| 组合 | MAP mean/sd | SBP mean/sd | DBP mean/sd | 过档 |
|---|---|---|---|---|
| A 旧轴 + 旧偏移（当前提交状态） | −0.50 / 4.03 | **+0.50 / 6.31** | +2.26 / 3.73 | **6/7**（P2 失败） |

**P4 SBP 从 −2.91 变成 −5.88** —— 旧轴在 P4 那一档的系统偏移是 −2.97 mmHg，正好把误差推向 0。
换句话说，**原来那个"6/7"里有一档是尺子错了之后碰巧对的**。

### 6.2 T0 可声明格：0/21 → 2/21

把每档的轴移加到冻结 T0 的格均值上（半宽不变，`tmp\axis_t0b_20261125.py`）：

**21 格从 0 格可声明变成 2 格可声明**，其余 19 格仍 undecided（半宽中位 4.61 太大）。
注意这两格的余量很薄（4.59 与 4.96 对 5.00），**不能当作稳健结论**，只能说"修好尺子后
终于有两格摸到了边"。

### 6.3 T3 对轴误差免疫

用 `tools\crosstday_judge.py:280` 的 `two_way()` 直接跑新旧两套值（`tmp\axis_anova2_20261125.py`）：

| 量 | 旧轴 | 新轴 |
|---|---|---|
| SBP `sw / sb / F / p` | 5.537 / 0.000 / 1.949 / **0.04661** | 5.484 / 0.000 / 1.950 / **0.04643** |
| MAP p | 0.00057 | 0.00056 |
| DBP p | 0.00150 | 0.00150 |

**日项判定完全不变**，因为轴误差是压力档位的函数，被模型的 preset 主效应完整吸收。
这是一条方法论结论：**换标定不会改变"日效应存在"的判断，只会改变绝对准确度。**

### 6.4 轴误差只占方差的一小部分

`tmp\axis_variance_20261125.py`（把每档的轴移当成一个可解释项）：

| 量 | 总 sd | 轴移贡献 sd | 剩余 sd | 轴解释的方差 |
|---|---|---|---|---|
| MAP | 4.03 | 0.51 | 4.00 | 1.6 % |
| SBP | 6.31 | 0.56 | 6.28 | 0.8 % |

**所以修轴修的是"偏"，不是"抖"。** 单次测量的 95 % 区间仍然是 MAP ±7.9 / SBP ±12.4 / DBP ±7.3。
要让这些区间变窄，得改采集与估计器，不是改尺子。

```

```

## 10 还缺什么

1. **268–275 mmHg 仍零测量**（本次最高 242.0）。要收口需先抬 `BP_MAX_PRESSURE_MMHG 280`。
2. **`BP_Cal_Write()` 不擦页**，任何改标定都要先 `cal clear`；这是固件缺陷，建议下一批之前修。
3. **H1/H2 仍未分离**：新斜率 81.5286 隐含供电 **5.1994 V**，实测轨 **5.133/5.149 V**，
   差 1 %；旧斜率隐含 5.0616 V。要么找一台精密 5.000 V 源做供电实验，要么接受"器件增益比
   手册典型高 1 %"。
4. **温度项、压力迟滞、长期偏移稳定性**仍未测（手册 `Offset Stability ±0.5 %VFSS`）。
5. **`tools/covered_bp.py` 的偏移常量没有随轴改**：改了必须出 v6 或 amend，否则会污染已发表
   语料的复现链。
6. **每轮零点在 0 处系统性偏高 2.5–3.8 mmHg**（三组 sweep 的 `zero_drift.mcu_mmhg` 是
   2.5/3.7/3.8，Tester 报 4.0）——这是气路弛豫未完全结束还是标定，需要单独查。
