# 数据集说明 —— 非人体台架示波法袖带压力波形

本目录是可复现的非人体台架数据集：BP Pump 2 模拟人体血压与脉搏，STM32F103ZET6 固件
采集袖带压力与示波包络并导出原始波形。

**不是临床数据，不能用于准确性结论或替代 ISO 81060-2 验证。**

| `<run_id>.metadata.json` | 面板设置、固件版本、校准读回、漏气率、气路证据、分析结果 | **是** |
| `<run_id>.ndjson` | 桥接层原始日志：`[Pressure]` 20 Hz 文本流、命令回显、`bp.capture/4` 记录 | **否**（见下） |

> **2026-11-26 起逐样本遥测 `<run_id>.ndjson` 不再跟踪。** 移出版本库的是 `data/raw` 下
> 1016 份（1008 份 `*.ndjson` + 8 份 `*.jsonl`）、2208 MiB，占 `data/raw` 的 88%；
> `tools/reference_bp.py:83-108` 的 `load()` 只读导出帧里的
> `p`/`e`/`s`，没有任何估计器读它。唯一被报告引用的内容是固件自己打的
> `[BP] SBP=… DBP=… Pulse=… bpm valid=1`，这一行既不在导出帧也不在元数据里，
> 已抽成 `data/device_verdicts.json`（653 轮，`valid 278` / `calculation_failed 375`），
> 由 `tools/extract_device_verdicts.py` 生成；`--verify` 在带遥测的树上逐轮重新推导再比对，
> 在没有遥测的克隆里退回"这轮还在、`panel_preset` 与记录一致"，末行会写明是哪一种。
> **要看逐样本波形必须回到采集台架重采**，或用 `git show <旧提交>` 取历史版本。

### 已发布语料：62 轮

本文档下列所有统计表都基于 **62 轮**，其构成是**推导出来的、不是选的**：

```
三个协议层      18 + 20 + 20 = 58
+ 补充轮        4（在 v3 预注册前采集的 Preset 4）
= 62
```

> **这 62 轮里有 4 轮被冻结门判 REJECTED**（`USABLE 58 / REJECTED 4`）：
> `…20261107-154020` −13.35、`…20261107-202606` −15.49（均在 `prospective_v1`）、
> `…20261107-212915` −32.87、`…20261107-215245` −16.81（均在 `prospective_v2`）。
> 原因是降压阀在 200–245 mmHg 窗内失节流（详见 `reports/deflate_throttle_loss_20261125.md`）。
> `tools/dataset_tiers.py:168-181` 的 `in_published_corpus()` 只看层、**不看 `gate` 列**，
> 所以"已发布"与"被门接受"是两个字段：引用 62 轮的统计时必须知道这 4 轮的压力剖面不合格。

分界点是 **2026-11-11T09:49:47**（冻结 v3 的 `5066fc5` 提交）。在此之后采集的
轮次必须先用于验收测试，因此在统计上被隔离。当前被隔离的是 40 轮 `v3_acceptance`

轮次）加 **266 轮 `crosstday`**（2026-11-16 至 11-25 的跨天批次，自带预注册协议与

    但它在唯一的留出层 `v3_acceptance` 上把池化偏置从 **−3.07 推到 −4.73**（sd 5.72→5.69 不动），
    且池化 `corr(自己的 MAP, 误差) = −0.354` 而逐档全为正（辛普森）→ **编码的是档位身份不是物理**；
    包络峰幅度规则等于无规则（4/7）；估出脉搏压规则 5/7 但池化 sd **7.27→8.50**。
    早先记的"4/7→3/7"来自 `tmp/sbp_linear_rule_current_20261115.py:55` 把模型偏置**又加了一遍**
    （正确方向是减去），那条记录已作废。
    **SBP 的误差主要是脉压的 2/3**：`e_sbp = e_map + (2/3)·e_pp − note_gap` 在 126/308 轮精确
    成立（最差 0.667 mmHg），`PP_est` 对 `PP_panel` 的斜率只有 **+0.657**（脉压被压缩）；
    但**反压缩 0/7**（脉压误差 75.5% 在档内、档内 sd 7.02 ≈ 档间 7.6，三视图 SNR 0.41–0.98
    无一接近 3，池化 sd 6.27→12.49），`SBP = 3·MAP − 2·DBP` 也 **0/7**
    （`corr(e_map, e_dbp) = −0.046`，误差相加），估算器三输出互不自洽（残差 +2.09…+9.58）。
    **唯一能到 7/7 的是加性偏移 −0.5**（sd 一位不动），但开发集 **+2.00** 与留出层 **−3.07**
    符号相反、差 5.07；留一日重拟合偏移很稳（MAP 0.42 / DBP 0.46）—— **不是可迁移常数**。
    **封阀零点是唯一物理正确的修正**（within-day 对 SBP 斜率 +0.931），但日间零点只变 1.67、
    SBP 日间误差跨度 6.94 → 最多解释 3.74，re-zero 后判定仍 5/7。
    更根本的是 `corr(面板 MAP, 每搏容积) = −0.995`——七个预设**设计上**让两者一起动，
    所以"偏置跟 MAP"与"偏置跟容积"在这批数据上无法区分。**打破共线的协议依据成立
    （两假设相距 8.0 mmHg、2σ 需 4–6 轮/臂），但已暂缓**：它解释的量小于它能分辨的下限，
    且手册 Table 3-3 里唯一同压力配对 Healthy/Obese 心率同时差 15 bpm、
    带通 `1.0–2.0 Hz` 只覆盖 60–120 bpm。
    还能改的一条：**批次按天摊开**（只降批次均值的 SE：P7 SBP 1 天 3.89 / 4 天 2.25 /
    8 天 1.84，**不动单次 sd**）。**不得说"精度已到极限"，不得说"P5/P7 的 SBP 不达标"，
    不得把面板 MAP 当偏置的原因，不得说"线性规则把覆盖提到 7/7 是改进"，
    也不得说"把 `SBP_OFFSET_MMHG` 改成 −0.5 就能达标"**，
    更不得说 P2 是靠剔数据过掉的（是重采 2 轮 + 标签处置，默认口径未改）。
    详见 `reports/precision_levers_20261115.md` 与
    `reports/sbp_levers_after_unresolved_20261115.md`。
