# freeze v5 预注册：三视图中位估计器（七档共用一套常量）

**声明时间：2026-11-13 晚（本地）**
**状态：预注册（候选）。验收标准在看到任何 v5 批次数据之前写死，之后不得修改。**

本文件不是估算器冻结记录的替代，也不是对 `tools/reference_bp.py` 的修改。三份既有冻结记录
（v1 / v2 / v3）的估算器文件与常量全部不动，`tools/verify_freeze.py` 必须继续报三份完好。
本文件冻结的是**一个新的候选估算器** `tools/covered_bp.py`，以及为验证它而新采集哪批数据、
用什么标准判定成立。

---

## 1 动机（全部来自既有证据）

`data/reports/covered_algorithm_20261113.md` 给出的事实：

- 冻结 v2 在七档语料上**没有任何一档三项同时过 AAMI**，且有 **18 轮静默大错**（发布了数字
  但某一项误差 >20 mmHg，最坏 MAP +149.6）。
- 同一批 222 份导出上，`tools/covered_bp.py` 用**一套常量**（无任何按档参数）做到 7/7 档三项全过、
  静默 >20 归零，出数率与冻结 v2 **完全相同**（187/222）。
- 改善机制不是"赢在改分母"：只保留三视图都发布的轮、仍用 firmware 答案的子集，依然是 0/3 档、
  静默 17（vs 全集 18）；配对 168 轮上 SBP 变好 43 / 变差 6、DBP 36 / 2、MAP 54 / 40。

**但这套规则是在看完全部 222 轮之后设计的。** 所以它只能支持"值得做一次前瞻验证"，
不能支持"v5 已经成立"。本预注册就是那次验证。

## 2 被验证的对象（写死，不得在验收时改动）

> **v5 估计器 := 三个包络视图（设备包络 / 1.0–2.0 Hz 心率带包络 / 两者几何融合）各自用冻结
> `reference_bp.estimate` 求解；取已发布视图的逐参数中位；加 MAP −5.31、DBP −1.16 两个加性偏移
> （SBP 不加）；过两道门限（脉搏压 ≥ 0.15·SBP、|MAP − (SBP+2·DBP)/3| ≤ 10 mmHg）才发布。**

实现即 `tools/covered_bp.py` 当前提交版本。**九个常量全部写死**：

| 常量 | 值 | 来源 |
|---|---|---|
| `FS_HZ` | 40.0 | `bp.capture/4` 每 25 ms 一个点 |
| `BAND_HZ` | (1.0, 2.0) | 面板七档 BPM 恒 80 = 1.33 Hz；台架极限环 0.62–0.90 Hz |
| `SMOOTH_S` | 2.0 | 与冻结估算器的中位窗一致 |
| `MIN_VIEWS` | 2 | 中位需要两票 |
| `PULSE_PRESSURE_FRACTION` | 0.15 | 形态门限，最宽的一档 |
| `NOTE_GAP_MMHG` | 10.0 | 落在 9.0–12.5 的平台中央 |
| `MAP_OFFSET_MMHG` | −5.31 | `frozen_baseline_v2` 14 轮拟合 |
| `DBP_OFFSET_MMHG` | −1.16 | 同上 |
| `SBP_OFFSET_MMHG` | 0.0 | 故意不加（见报告 §4） |

**验收期间不得改这九个值中的任何一个。** 包括"把带宽微调一点会更好"——那需要另一次预注册。

## 3 验收标准（事前写死，四条全过才算 v5 成立）

对**新采集的 v5 批次**（见 §5），逐项指标独立判定：

**C1（精度，硬门栏）** 三项（MAP / SBP / DBP）的池化 sd 都 ≤ 8.0 mmHg，且 |mean| 都 ≤ 5.0 mmHg。
沿用 AAMI 口径，池化 = 该批次全部已发布轮。

**C2（相对冻结 v2 的改善是真的）** 在同一批采集上，v5 的三项 sd 比冻结 v2 各低至少 1.0 mmHg。
这条防"这批数据本身很干净所以怎么样都过"，也防"v5 只是拒判更多所以看起来更好"——
**因此 C2 必须在两边都发布的交集上算**，不是各算各的分母。

**C3（不许用偏移换精度）** v5 的三项均值偏差绝对值不比同批次冻结 v2 恶化超过 1.0 mmHg。
v3 的教训：把 sd 降下来但把均值推走，不算改进。

**C4（发布率不塌）** 该批次里 v5 发布的比例 ≥ **0.80**。
定 0.80 而不是 v4 的 0.90 的理由：v5 的拒判是设计的一部分，它在开发语料上挡掉了 24 份本会
发布出去的两位数误差答案，代价是 30 份拒判（其中误伤 4 份）。开发语料实测发布率是
187/222 = **0.842**，所以 0.80 留了余量；**若定 0.85 就高于开发实测值，那是在给自己设一个
已知过不了的门槛**。这一条现在写死，验收时不得下调。

**C5（不许再有静默大错）** 该批次里，已发布轮中任一项 |误差| > 20 mmHg 的轮数 = **0**。
开发语料里这条是从 18 降到 0 的主要卖点之一，如果新批次上出现任何一轮，v5 的直接价值就没了。

**判定规则：任何一条不满足，v5 被否决，数据集继续以冻结 v2 的结果作为参考算法输出
（并在每次引用时注明它是 0/7 档达标、有 18 轮静默 >20），不得改口说"新版本更好"。**

## 4 排除规则（采集前声明，逐字沿用 v3 的八条）

1. 严格解码器拒绝的轮次排除（含单点丢失，如 `20261113-162512`）。
2. 预检失败且未发生充气的轮次排除。
3. 采集期间 MCU 报故障的轮次排除。
4. `vent → seal` 收尾未确认封阀零点的轮次排除。
5. 被 `tools/validity_v2.py` 判为不可用的轮次排除。
6. v5 拒判的轮次**标记但不排除**：它是该批次的一次采集，只是没有答案；C1–C3 用它之外的数据算，
   C4 用它来算发布率。
7. **不得因为某轮答案与面板不符而排除它。**
8. **不得把既有 229 轮里的任何一轮计入 v5 验收。**（`tools/dataset_tiers.py` 的
   `PUBLISHED_AT = 2026-11-11T09:49:47` 与新批次时间戳可自动区分；`supplementary` 层的 123 轮
   同样不得计入。）

## 5 采集计划

七档各采 **10 轮**，共 70 轮，每轮实测墙钟约 3.5 min → **≈4.1 h**。按 §1 的每档表现分配：

| 预设 | 面板 | 开发语料发布率 | 新采轮数 | 理由 |
|---|---|---|---|---|
| #1 | 120/80 | 74/78 | 10 | 主档，任何改动都要先在这档不退化 |
| #2 | 150/100 | 19/23 | 10 | 样本少（n=23），需要补 |
| #3 | 200/150 | 16/23 | 10 | **发布率最低（0.70）**，是 C4 的风险点 |
| #4 | 255/195 | 47/65 | 10 | 冻结 v2 最差的一档（SBP −5.78/11.37、DBP +8.59/8.28） |
| #5 | 60/30 | 11/11 | 10 | 飞轮档，v5 的主要卖点在这 |
| #6 | 80/50 | 10/11 | 10 | |
| #7 | 100/65 | 10/11 | 10 | |

- 每档 10 轮按 AAMI 口径**不足以给出可信的 sd 上界**（n=10 时 sd 的点估计噪声很大）。
  所以 C1–C3 一律以**池化**（全部已发布轮）判定，逐档结果只作方向性报告，不作声称。
- 若要做逐档的 sd 上界声明，需按 `tools/measurement_precision.py` 的 `_groups_needed` 反推，
  方法同 `data/protocols/reference_bp_freeze_v4_candidate.md` §5；那远超本批预算。
- 采集用 `tmp/run_preset_sweep_20261113.py`（每档先发 `[SIM_STD*]`，只有 ACK 才继续），
  每档之间不必重刷固件——**本预注册不涉及任何固件改动**，`firmware_hex_sha256` 应保持
  `61ca1da309439d9a…`（184146 B）不变；若变了说明刷过固件，该批数据不得计入。

## 6 采集期间允许的判据修订（不是验收标准的一部分）

沿用 v4 §6 的修订记录：采集有效性判据是"未钳位真零点对称 ±5.0 mmHg"
（`PRE_CAPTURE_ZERO_GATE_MMHG = 5.0`），不是被 `ads1115.c:215-218` 钳到非负的 `est ≤ 1.2`。
依据与细节见 `data/reports/zero_drift_20261112.md`。**这条属于采集有效性，不属于估算器常量，
修订不需要重新预注册；四条验收标准与九个常量都不许动。**

## 7 这一批数据不得用来做的四件事

1. 不得用来重选带宽、平滑宽、门限、偏移中的任何一个。九个常量已在 §2 写死。
2. 不得用来换聚合方式（中位改均值、两视图改三视图）。
3. 不得混入既有 229 轮一起算 C1–C3。v5 批次的数字必须单独报告，并与冻结 v2 在同一批次上对照（C2）。
4. 不得在验收失败后把 C4 从 0.80 下调、或把 C5 从"=0"改成"≤1"。

## 8 复现

```powershell
# 1. 采一批（每档 10 轮；每轮之间用 v2 守门，任一失败按 §4 记账）
python tmp\run_preset_sweep_20261113.py --rounds 10 --presets 1,2,3,4,5,6,7 --tag-suffix v5

# 2. 判 C1..C5
python tools\covered_bp.py --score --glob "data/raw/development_20261101/standard*_peakwindow_2026111[4-9]-*.export.ndjson" `
    --json data\reports\v5_validation_groups.json

# 3. 同批次上的冻结 v2 对照（C2、C3）
python tmp\covered_compare_incumbent_20261113.py --glob "同上"

# 4. 确认冻结配置与固件都没动
python tools\verify_freeze.py
```

`--glob` 的具体日期串在采集当天确定（本文件不预写死日期，避免与实际采集日不符时产生歧义）；
判定脚本必须在看到结果之前先对同一 glob 跑一次 dry-run，确认它恰好选中本批次、且不含任何
2026-11-13 及之前的文件。

## 9 与既有记录的关系

- v1 / v2 / v3 冻结的是**估算器**与其常量，三份记录逐字节可验证，本文件不动它们。
- v4 冻结的是**测量单位**（k 次采集的中位），与估算器正交；v4 的 P1 结论与 P4 否决都继续有效。
- 本文件冻结的是**一个新的候选估算器**与验证它的数据。它的产出一句话能不能写：
  "在 70 轮前瞻采集上，一套常量通吃七档的 v5 估计器池化 sd = X / Y / Z mmHg（n = N 轮），
  静默 >20 mmHg 为 0，发布率 P，同期冻结 v2 在同一批上是 …"。
- 如果 C1–C5 全过，`data/reports/covered_algorithm_20261113.md` 里"不能写"的第 1、2 条可以
  改成前瞻验证过的结论；如果不过，那份报告与 `dataset_limitations.md` §18 的现有表述继续有效。
- **不得把 v5 写成"设备算法"**：设备固件仍然把 MAP 搜索窗写死 80–100 mmHg
  （`bp_algorithm.c:534-541`），v5 是离线参考实现，不改变任何设备行为。
